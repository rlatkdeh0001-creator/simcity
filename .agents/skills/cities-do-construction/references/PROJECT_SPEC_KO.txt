Godot 시티빌더 시뮬레이션 게임 개발 명세서 (Codex 전달용)
버전: 기획 초안 v0.1 / 기준일: 2026-10-31

==============================
0. 코덱스에게 요청하는 작업 방식
==============================
이 문서는 앞으로 만들 게임의 기획 및 시스템 요구사항이다. 지금 즉시 모든 기능을 한 번에 완성하라는 뜻이 아니다.
먼저 구현 가능한 아키텍처와 단계별 개발 계획을 제안하고, 1차 MVP부터 실제 작동하는 Godot 프로젝트로 만들어라.
확정된 요구사항은 보존하고, 미정 수치·밸런스는 설정 파일 또는 리소스로 쉽게 수정할 수 있게 하라.
성능 최적화를 고려하여 시뮬레이션과 화면 렌더링을 분리하고, 모든 개체를 실시간 물리 객체로 만들지 말 것.
구현하지 않은 기능을 구현했다고 주장하지 말고, 완료·부분 구현·미구현을 매 단계 명시할 것.
모호한 결정이 중요한 아키텍처에 영향을 준다면 구현 전에 질문할 것.

==============================
1. 게임 정체성과 기본 방향
==============================
- 엔진: Godot. 언어는 우선 GDScript, 성능 병목이 확인되면 최적화 방안을 검토.
- 비주얼: SimCity 4 스타일의 2D 아이소메트릭 도시 건설 게임.
- 도로 건설은 격자 직선만이 아니라 자연스러운 직선·사선·곡선 지원.
- 실제 교통, 출퇴근, 경제활동, 주차, 대중교통, 신호 운영이 상호작용하는 도시 시뮬레이터.
- 도시 시간은 연속적으로 흐르며 일시정지와 배속 기능 제공. 기본 1배속에서 현실 시간 대비 게임 시간이 얼마나 흐를지는 최종 미정(초기안: 1초=게임 1초). 배속이 시뮬레이션 정확도를 깨지 않아야 함.
- 플레이어는 시정부 예산으로 도로·주차장·공공 인프라를 건설하고 유지. 시민과 기업은 별도의 돈/수입/지출을 가진다.
- 인구 수십만 명으로 확장 가능한 성능 지향 설계. 인구 10만 명을 초기 성능 기준 사례로 사용.

==============================
2. 내부 데이터 구조 핵심 원칙
==============================
- 도로의 외형(렌더링), 차로별 연결 그래프(경로), 교통 시뮬레이션 상태(차량량·대기열)는 분리.
- 지상·고가·지하 도로와 철도는 동일한 3차원 좌표계/고도 원칙 사용. 화면에서 아이소메트릭으로 투영.
- 도로는 내부적으로 여러 작은 세그먼트와 교차로/분기 노드로 나누어 계산한다.
- 유저에게는 '영화7길', '중앙대로' 같은 이름을 가진 긴 도로(Road ID) 하나로 표시할 수 있고, 그 아래 여러 세그먼트가 속한다.
- 경로 탐색은 연결 가능한 차로/진입·진출 방향을 기준으로 한다. 화면상 두 도로가 겹친다고 해서 자동 연결되는 것은 아니다.
- 시민은 전원 개별 물리 객체로 만들지 않는다. 주거·업무 건물별 집계와 출발지-목적지(OD) 이동 그룹을 사용한다. 같은 건물 주민도 목적지·출발시간·이동수단은 분산시킨다.
- 경로 캐시와 교통 수요 배치 계산을 사용. 화면상 자동차는 실제 교통량에서 파생한 시각 표현으로 처리할 수 있다.

==============================
3. 하루 24시간과 시민 이동
==============================
- 04:00~09:00: 긴 출근 시간대, 많은 시민이 분산 출발.
- 09:00~11:00: 차량 통행 감소.
- 11:00~13:00: 점심 이동으로 교통량 다소 증가.
- 13:00~17:00: 통행량 감소.
- 17:00~21:00: 긴 퇴근 시간대.
- 21:00~04:00: 심야에도 일정한 이동 수요 존재.
- 위 시간은 초기 도시 전체 수요 경향이며, 모든 시민이 동시에 움직이지 않도록 건물·직업·개별 일정과 확률 분포를 적용.
- 시민 그룹은 주거지, 직장, 소득, 행복도, 자동차 보유량, 출퇴근 패턴, 교통수단 선호, 지출과 불편 경험 등의 상태를 보유.
- 집↔직장만이 아니라 쇼핑·식사·여가 이동도 발생할 수 있다.
- 불편이 누적되면 교통수단 변경, 이직, 이주, 도시 이탈을 검토한다. 단발성 지각이나 택시 이용 한 번으로 바로 이탈하지 않음.

==============================
4. 차량 경로 선택 및 차로 변경
==============================
- 차량/이동 그룹이 출발할 때 목적지까지 예상 시간이 가장 유리한 초기 경로를 계산.
- 기본 철학: 한번 정한 경로를 되도록 끝까지 유지.
- 게임 시간 1분마다 현재 경로의 예상 시간을 재평가. 반드시 매번 전체 최단 경로를 처음부터 새로 탐색할 필요는 없음.
- 혼잡·사고·폐쇄 등으로 큰 이점이 예상될 때 대안 경로를 탐색/비교.
- 초기 제안 우회 기준(확정 밸런스 아님): 최소 5분 절약 AND 기존 경로 대비 최소 20% 단축. 길이가 길어져도 시간이 충분히 절약되면 우회 가능.
- 작은 차이로 연속해서 우회 경로를 바꾸지 않도록 히스테리시스/재변경 쿨다운 적용.
- 모든 이동 그룹이 같은 순간 재탐색하지 않도록 갱신 시점 분산. 동일한 OD/비슷한 속성의 경로는 캐시 활용.
- 차로는 일찍 정한다. 예정된 좌회전·분기·진출에 필요한 차로로 충분히 미리 이동하며, 무의미한 잦은 차로 변경은 피함.
- 경로가 변경되거나 필요한 경우에만 차로 변경. 차로 변경은 주변 통행 및 대기열에 영향을 미침.
- 거리보다 예상 소요 시간을 우선하되 차량마다 정보/선호에 차이를 주어 모든 차량이 동시에 동일한 우회로로 몰리지 않도록 함.

==============================
5. 도로 종류 및 건설
==============================
[일반도로: 양방향 차로 수 합계]
- 왕복 2차로 = 방향별 1+1
- 왕복 3차로 = 2+1 또는 1+2, 유저가 전환 버튼으로 많은 쪽 선택
- 왕복 4차로 = 2+2
- 왕복 5차로 = 3+2 또는 2+3, 유저가 전환 버튼으로 많은 쪽 선택
- 왕복 8차로 = 4+4
- 일반도로 옆에만 주거·상업·공업 건물 구획을 지정 가능(Cities: Skylines식 도로 인접 구획).

[고속도로]
- 왕복 2차로 = 1+1, 왕복 4차로 = 2+2(초기 종류 정의). 나들목/램프 지원.
- 고속도로에는 직접 건물 구획 불가.

[공통]
- 직선·곡선·사선, 분기·합류·교차로 지원.
- 도로는 유연하게 갈라지거나 합쳐질 수 있어야 함: 4차로 → 2차로+2차로, 역방향 합류도 가능.
- 일부 차로는 지상도로로, 다른 차로는 고가/지하로 분기 가능.
- 도로 폭/차로 수를 구간별로 바꿀 수 있음. 차로 연결 관계를 명시적으로 보관.
- 실제 도로 외형을 차선 경로 편집 때마다 변형할 필요는 없음. 차로 수 변경은 별도 건설 기능.
- 제한속도, 도로 건설비/유지비, 용량 등 구체 수치는 추후 밸런싱.

==============================
6. 3차원 고도·다리·터널·철도 교차
==============================
- 지면 기준 높이 0m, 기본 고가도로 +10m, 기본 지하도로/지하철 -10m.
- 높이 편집 단위는 5m. 지상과 다른 높이의 도로를 여러 층으로 중첩 건설 가능. 논리적인 층수 상한은 두지 않음(엔진 성능/표현상의 기술적 한계는 관리).
- [강한 확정 규칙] 어떤 도로/철도라도 서로 위아래로 겹쳐 지나가거나 입체 교차할 때 실제 겹치는 부분의 수직 간격이 반드시 10m 이상이어야 함. 도로↔도로, 도로↔철도, 철도↔철도, 고가↔지하 모두 적용.
- 두 시설이 멀리 떨어져 겹치지 않으면 높이 차이가 5m여도 허용 가능.
- 같은 레벨에서 서로 실제 연결하도록 설계한 평면교차로는 별도의 연결 규칙 적용.
- 건설 경로의 양 끝점만이 아니라 곡선·경사 중간 지점의 높이 및 구조물 전체 폭이 겹치는 영역을 검사.
- 고가·지하·다리·터널은 하나의 기본 교통망 구조를 공유하되 시각적 자산 및 비용/구조 속성을 구분.
- 높이가 올라가거나 지하로 깊어질수록 건설비·유지비 증가, 초기 제안은 비선형 증가(정확한 공식 미정).
- 경사 허용치 초기 제안: 일반도로 약 8%, 고속도로 약 5%. 정확한 게임 규칙은 추후 결정.
- 주차장 내부 층고는 위의 '도로/철도 사이 10m 입체교차 간격'과 별도 건축 규칙으로 취급.

[건설 미리보기 UX]
- 건설하려는 도로·철도 스프라이트/경로의 반투명 미리보기를 마우스 커서/드래그 위치에 표시.
- 설치 가능 = 초록색, 클릭해서 확정 가능.
- 설치 불가 = 빨간색, 확정 불가. 이유 표시(교차 수직 간격 부족, 급경사, 충돌, 돈 부족 등).
- 건설 및 편집 시 도로/차로 연결 그래프와 관련 경로 캐시를 적절히 갱신.

==============================
7. 교차로·차로 연결·신호등
==============================
- 일반 모드에서는 도로 유형에 맞춰 차로 방향/신호 자동 배정. 왕복 4차로의 기본 예시는 직진과 좌회전을 함께 허용하는 직좌 신호(실제 방향별 규칙은 안전하게 자동 생성).
- '심화 모드' 버튼으로 교차로에서 진입 차로 시작점과 진출 차로 끝점을 유저가 연결하여 허용 이동 경로를 편집.
- 예: 남북 중앙대로를 유지하면서 동서 옆길에서 중앙대로로만 합류 허용, 양쪽 옆길이 중앙대로를 가로질러 직진하는 이동은 금지. 중앙대로에서 옆길로 빠지는 이동도 개별 지정 가능.
- 사용자가 그린 차로 연결은 실제 도로 형상을 꼭 변경하지 않으며 통행 가능 그래프를 변경하는 기능.
- 접속 교차로의 차로 방향/충돌·합류·양보 관계를 분석.

[신호 제어 모드]
1) 자동: 연결된 이동 경로와 교통 수요를 고려해 신호를 자동 설정.
2) 수동: A/B/C... 각 신호 그룹의 점등 초수와 순서, 동시 점등 조합을 플레이어가 정의. 예: A+C 동시 녹색 35초 → 안전 전환 → B 녹색 25초 → 안전 전환 → 반복.
3) 무신호: 우선도로·양보·정지 규칙으로 운영.
- 신호 그룹은 임의 개수의 차로 이동 연결과 매핑 가능.
- 양립 불가능한 동시 녹색은 충돌 검사로 경고/기본 차단. 양보 허용 이동은 별도 규칙으로 처리.
- 황색/전적색 안전 전환 시간을 고려.
- 향후 확장: 신호 연동(녹색 물결), 시간대별 신호, 교통량 감응, 버스/긴급차량 우선.

==============================
8. 교통 흐름·사고 모델
==============================
- 화면 속 차량들을 모두 물리적으로 충돌시키지 않음.
- 차로/도로 구간별 차량 수, 유입·유출, 속도, 대기열, 교차로 신호 용량을 집계 계산.
- 차선별 좌회전 대기와 직진 흐름의 차이 등을 표현. 합류·교차·주차 등으로 유효 도로 용량 변화.
- 사고는 복잡도·차량 통행량·합류·교차 동작·속도·차로 변경 등에 따른 확률로 발생.
- 사고는 실제 충돌 물리 재현 대신 해당 도로/차로의 용량 감소와 지연으로 반영. 지속 시간 이후 해소.
- 동일 사고 확률을 시간 단위와 교통 노출량에 맞춰 계산하여 배속을 올려도 사고 발생률이 비정상적으로 증가하지 않게 한다.
- 사고/정체로 예상 시간이 크게 변하면 이동 그룹은 기존 경로 유지 원칙 아래 대안 경로를 검토.

==============================
9. 도로 이름과 '도로 특화' UI
==============================
- 유저가 도로를 클릭하면 '도로 특화' 탭 표시.
- 내부 구간별 ID와 별개로, 여러 연속 세그먼트에 도로 ID와 이름을 부여. 예: '영화7길'.
- 일자로 자연스럽게 이어지는 구간은 하나의 도로 이름으로 묶는 것을 기본 제안. 분기/교차로처럼 연결 방향이 모호하면 유저 확인 또는 편집 지원.
- 기본 적용 범위 = 같은 도로 이름/ID의 전체 구간. 필요하면 선택 구간만 별도로 수정.
- 기본 UI = 도로 이름, 주차 정책, 제한속도.
- 고급 UI = 일방통행, 버스 전용차로, 화물차 제한, 시간대별 주차 정책, 교통량/평균 속도 통계.
- 같은 도로 아래 여러 구간의 제한속도/차로 수/고도가 달라도 이름이 유지될 수 있음.
- [보류] 양쪽 갓길의 주차 정책을 좌·우 별도로 지정하는 기능. 초기에는 도로/선택 구간 양쪽에 동일하게 적용하고, 추후 UX 검토.

==============================
10. 주차·갓길·택시
==============================
- 모든 개인 자동차는 어딘가에 주차 공간이 필요. 출근·쇼핑 시 목적지에서도 주차 공간을 확보해야 함.
- 주거 건물별 설계상 주차 공급률의 기본 범위는 자동차 수요 대비 약 90~110%, 기본값은 100%. 정확한 공급량은 건물 종류에 따라 다름.
- 전원주택은 보통 주차 비율 100%이지만, 성인 4명이 각각 차를 갖는 등 실제 보유 차량이 늘면 부족할 수 있음.
- 맨션/다세대 주택은 인구 밀도에 비해 주차 공간 부족이 드러나는 경향.
- 주거타워는 여유 주차 공간이 있을 수 있음. 남는 공간 임대 시스템 자체는 초기 구현 불필요.
- 상업시설: 소규모 상점은 자체 주차장 없음; 중규모 식료품점은 넉넉한 주차장; 자동차 부품 대리점은 어느 정도 주차 공간; 중/대형 시설은 업종·규모별 차등.
- 공영/민영 주차시설 건설 가능: 지상 주차장, 주차타워, 지하 주차장. 건설/유지비, 용량과 위치 접근성 차등.
- 자체 주차 공간 부족 시 주변 주차장을 탐색하고 주차비와 도보 접근 시간을 부담. 부족이 지속되면 행복도·상업 방문·차량 보유/선택에 영향.
- 모든 일반도로의 갓길에 기본적으로 주차 시도 가능. 단, '도로 특화'에서 전체 도로 또는 선택 구간의 갓길 주차 허용/금지/시간제를 설정 가능.
- 갓길 주차 차량이 있으면 해당 방향 차로의 유효 폭과 통행 용량이 줄고 통과 지연이 발생. 왕복 2차로(1+1)에서는 특히 심하게 영향을 받을 수 있으나, 도로 전체가 문자 그대로 편도 1차로로 전환되는 것은 아님.
- 주차금지로 통행은 개선될 수 있지만 대체 주차장이 없으면 방문객 감소·상업 매출 감소·행복도 하락 가능.
- 자동차 보유율과 실제 이용률은 구분. 소득, 주차비, 대중교통 편리성, 주거·직장 위치에 영향을 받음.

[택시]
- 자정 부근에 지하철·버스 막차가 종료됨(정확한 노선별 막차 시각은 미정/설정 가능).
- 시민이 귀가하려는데 도보/대중교통 등 현실적인 대안이 없으면 택시 호출.
- 도시 내부 택시가 부족하면 외부 도시에서 택시를 호출할 수 있음. 외부 택시는 요금과 대기 시간이 더 큼.
- 택시 요금은 시정부 예산이 아닌 시민의 개인 돈에서 나감. 반복되면 가처분소득과 행복도 하락, 장기적으로 도시 이탈 가능.
- 외부 택시는 승하차/일시 대기 공간이 필요하지만 주민처럼 상시 주차면을 점유하지는 않음.

==============================
11. 건물 구획 및 성장
==============================
- 일반도로 인접 지점에 주거/상업/공업 구획 지정. 수요에 따라 적합한 건물이 자연 발생하고 성장·쇠퇴.
- 주거: 초기 전원 단독주택(예: 4인 가족) → 다세대/맨션 → 중층 아파트 → 고층 주거타워. 인구·일자리·소득·지가·교통·생활편의성에 영향.
- 상업: 식료품점/생활용품점 → 가전제품 판매점 등 → 백화점/명품 매장 등. 시민 소비력, 방문 수요, 상품 공급에 영향.
- 공업: 빵공장/소시지 공장 등 식품 가공 → 더 복잡한 제조업/자동차 부품 공장 등. 노동력·물류·원재료·기술 수준에 영향.
- 자동차 부품 '대리점'은 판매/유통 상업시설, '공장'은 공업시설로 구별.
- 건물의 밀도/크기와 업종의 발전을 별도 축으로 관리. 도시가 부유해져도 모든 단독주택·식료품점이 사라지는 일률적 업그레이드가 되지 않게 함.
- 적절한 소비자가 없거나 교통·물류 문제가 크면 업종 변경·성장 둔화·폐업 가능.

==============================
12. 경제·생산·수입·수출
==============================
- 시정부·시민·기업의 경제를 분리.
- 시정부: 세금 등 공공수입, 도로·공공시설 건설비와 유지비 지출.
- 시민: 임금 등 수입, 식비·쇼핑·주거비·교통비·주차비·택시비·세금 지출.
- 상업: 상품 판매 매출, 상품 매입·임금·임차료·세금 지출.
- 공업: 상품 생산/판매/수출 매출, 원재료·임금·물류비·세금 지출.
- 도시 내부 공급이 수요보다 적으면 부족한 재화는 외부 도시에서 구매 가능. 수입 재화는 운송비/외부 프리미엄 때문에 대체로 더 비쌈.
- 외부에서 물건을 사는 비용은 상품 구매자(시민·기업)의 돈에서 나가며 시정부 예산에서 자동 공제하지 않음.
- 도시 안에서 생산한 재화가 남으면 외부에 수출 가능하게 설계(제안 채택).
- 시민의 소득과 소비가 상업 매출을 만들고, 상업 주문이 공업 생산과 물류를 유발. 고용/임금/세수가 다시 인구와 소비에 영향을 줌.
- 예시 재화 범주(초기 제안, 최종 확정 아님): 식품, 생활용품, 가전, 자동차·기계, 의류·패션, 사치품, 건설자재, 산업 원자재. 세부품목은 확장 가능하게 설계.
- '도시의 개발 방향에 따라 돈이 들어오는' 경제를 지향하되 무조건 시간 경과만으로 보상금을 지급하는 방식은 피함. 세금·소비·생산·거래를 주된 수익 원천으로 모델링.

==============================
13. 상품 물류와 교통의 결합
==============================
- 공장→상점, 공장→외부, 외부→상점/공장, 시민→상점, 시민→직장 이동이 도로·철도/대중교통망의 수요를 만든다.
- 상품 단위마다 개별 차량을 만들지 말고 화물 단위/배치로 묶어서 운송 수요 계산.
- 공장·상점의 공급 지연은 재고와 매출/생산성에 영향.
- 교통체증·긴 통근시간·주차난은 기업 운영과 시민 행복도에 부정적 영향을 줄 수 있음.
- 시민과 기업의 자금 부족/수요 부족은 주거·상업·공업의 성장과 쇠퇴를 결정.

==============================
14. 권장 구현 아키텍처
==============================
Godot 장면/화면 표현과 별도로 순수 시뮬레이션 데이터 구조와 서비스를 마련:
- World/SimulationClock: 게임 시각, 배속, 고정 시뮬레이션 틱 및 일정 이벤트.
- Terrain/BuildValidator: 지형·고도·경사·교차 간격 및 비용 검증, 초록/빨강 프리뷰.
- RoadNetwork/RoadRegistry: 이름 붙은 도로와 하위 세그먼트, 차로, 3D 기하, 접속 노드.
- LaneConnection/IntersectionController: 진입·진출 연결, 자동/수동/무신호, 충돌/양보 관계.
- TrafficDemand/TripManager: 건물별 출퇴근·쇼핑·물류 수요 생성, OD 그룹.
- RoutePlanner/RouteCache: 최초 경로, 1분 주기 재평가, 선택적 재탐색, 시간 절약 기준.
- TrafficFlow: 차로별 점유·유입·유출·대기열·속도·정체·차로 변경 추상화.
- IncidentSystem: 확률 사고와 차로/도로 용량 페널티.
- ParkingSystem: 건물 주차 수요·공급, 갓길, 주차장, 불편/요금.
- TransitSystem: 버스·지하철 운행 시간/막차, 택시·외부 택시.
- EconomySystem: 시민·기업·시정부 회계, 상품 수요/생산·수입·수출·물류.
- Zoning/BuildingGrowth: 구획 수요와 건물 종류·규모·밀도의 변화.
- UI: 아이소메트릭 맵, 건설 도구, 도로 특화 탭, 교차로 심화 모드, 교통/경제 오버레이.
- SaveLoad: 도로망·규칙·건물·경제·시민 그룹·게임시간의 직렬화.

초기 성능 설계 원칙:
- 모든 시민을 Godot Node/CharacterBody로 만들지 않는다.
- 시뮬레이션 틱과 렌더링 프레임을 분리한다.
- 도로 변경 시 영향받는 그래프·캐시만 무효화한다.
- 경로 재평가는 게임 1분 단위, 필요시 분산/캐싱한다.
- 실제 10만 시민 도시와 수천 도로 구간을 가정한 프로파일링 테스트를 만든다.
- 배속 중에도 계산 결과가 지나치게 달라지지 않는지 테스트한다.

==============================
15. 단계별 구현 제안 (Codex가 계획 제시 후 진행)
==============================
Phase 1 — Godot 기본 프로젝트: 아이소메트릭 카메라, 지도, 시간/일시정지/배속, 저장 구조.
Phase 2 — 도로 그래프/건설: 직선·곡선, 종류/차로, 세그먼트/도로 이름, 분기·합류, 3D 고도, 겹침 간격 검증, 초록/빨강 미리보기.
Phase 3 — 차량 흐름: OD 수요, 출퇴근 시간 분포, 차로별 대기열, 경로 계산/캐시/1분 갱신, 화면 차량 표현.
Phase 4 — 교차로 심화: 차로 연결 편집, 자동/수동/무신호, 신호 그룹 동시 점등, 사고 및 용량 페널티.
Phase 5 — 주차·도로 특화: 주차 수요·갓길 주차·도로별 일괄 정책·도로명/통계, 주차장 시설.
Phase 6 — 대중교통: 버스·지하철 일정/막차, 택시/외부 택시, 귀가 불편 누적.
Phase 7 — 경제·구획 성장: 주거/상업/공업 수요, 상품 생산·거래·수입/수출, 화물, 시민/기업/시정부 경제, 행복도·이주.
Phase 8 — 밸런스·최적화·콘텐츠 확장: 도시 10만 명 성능 시험, 도로/건물 아트, UI, 수치 튜닝.

==============================
16. 미정/보류 사항과 코덱스 주의점
==============================
[미정: 설계/밸런싱 필요]
- 1배속 시간 비율, 최대 배속, 시간 단위 및 주요 시설 운영시간.
- 도로 제한속도·기본 용량·신호 안전 전환 시간·교통사고 확률.
- 경로 전환의 정확한 임계값(5분+20%는 초기 제안).
- 차로 변경 시작 거리, 병목 유효용량 공식, 택시 대기/요금과 외부 프리미엄.
- 인구 그룹 세부 집계 방식, 주거지당 차량 보유 분포 및 상세 주차 수치.
- 높이별 공사/유지비, 경사 최대치(8%/5%는 초기 제안), 지하 구조물 조건.
- 세금 및 물가, 외부 수입 추가 비용, 산업 재화 세부 목록, 성장/쇠퇴 임계값.
- 모바일 지원/최종 배포 플랫폼, 아트 해상도, 지형 크기 등.

[명시적 보류]
- 같은 도로의 양쪽 갓길을 서로 다른 주차 정책으로 별도 설정하는 UI. 추후 검토.
- 주거타워의 여유 주차면 임대 경제 기능(여유분 존재 자체만 반영 가능).

[혼동 금지]
- '왕복 4차로'는 기본 2+2이고, '편도 4차로'와 혼동하지 말 것.
- 높이 5m 단위로 건설하되 위아래로 교차하는 별개의 도로/철도는 무조건 최소 10m 이격.
- 고가·터널의 높이 차이 규칙은 교차 위치 기준이고, 모든 도로를 동일 고도 층으로만 제한한다는 뜻은 아님.
- 1분마다 현재 경로 '재평가'이지 모든 차를 무조건 새 경로로 보내는 것이 아님.
- 갓길 주차는 차량 물리 충돌 대신 차로 용량·속도·대기 페널티로 표현.
- 외부 재화 구매/택시 비용은 시민 또는 기업에 청구하고 시정부에 청구하지 않음.
- 건물의 발전은 모든 시설이 같은 선형 업그레이드 트리를 따르는 것이 아님.
- 초기 MVP에서 모든 시스템을 동시 구현하려 하지 말고 검증 가능한 최소 기능부터 확장.

==============================
17. 코덱스 첫 응답에 기대하는 내용
==============================
1) 위 요구를 반영한 Godot 프로젝트 구조 및 핵심 클래스/리소스 설계.
