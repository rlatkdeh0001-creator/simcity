## 조작

- 2×2 건설: 일반도로 옆 빈 셀을 클릭. 초록 미리보기는 가능, 빨강은 불가.
- 자유 도로: 지도에서 마우스 왼쪽 버튼을 누른 채 드래그 후 놓기.
  좌표는 격자에 스냅하지 않습니다. 충돌·경계 오류가 있으면 확정하지 않습니다.
- 건물 선택: 건물의 지붕 또는 부지를 클릭.
- 수치 +100 / 업그레이드: 선택한 건물 성장. 옆 건물이 확률적으로 함께 성장.
- 도시 초기화: 전체 지우기. 도로부터 다시 그릴 수 있습니다.

시작 시에는 빈 100×100 지형이며 격자가 보이지 않습니다. 자유 도로를 그리면
주변 건설 구획이 표시됩니다. 도로 선택 상자에서 왕복 2차로(1+1, 폭 2칸)와
4차로(2+2, 폭 4칸)를 선택하세요. 1칸=4m이고 폭에는 보도가 포함됩니다.
마우스 휠로 커서 위치를 중심으로 확대/축소하고 가운데 버튼 드래그로 이동합니다.
지도 크기는 maps/example_100.json에서 변경합니다.
건설 비용·경제·자동 시간 성장·저장/불러오기는 이 MVP 범위에 없습니다.

## 구조

- core/city_model.gd: 도로별 정수 부지 좌표, 연속 월드 좌표 도로, 폭을 고려한 충돌, 가중 성장, 연쇄.
- core/growth_config.gd: 크기 확률·기준 수치·연쇄 확률·최대 개수·도로 접근 거리.
- main.gd: 아이소메트릭 투영, 건설 미리보기, 자유 드래그, 선택과 성장 UI.
- ../.agents/skills/cities-do-construction: 재사용 개발 스킬 및 기획 참고 자료.

## 검증

```sh
godot --headless --path cities_do --script tests/test_city.gd
godot --headless --path cities_do --script tests/test_ui.gd
```

클라우드에서 사용자 데이터 폴더 권한이 없으면 다음 환경 변수를 명령 앞에 붙입니다.
`XDG_DATA_HOME=/tmp/cities-do-data XDG_CONFIG_HOME=/tmp/cities-do-config XDG_CACHE_HOME=/tmp/cities-do-cache`

로직 테스트는 공간·확률·연쇄 및 100회 성장 불변성을 검증합니다.
UI 테스트는 실제 장면을 띄워 입력 이벤트·버튼 신호·데이터 반영을 headless로 확인합니다.
그래픽 화면의 실제 시각 검수와 마우스 장치를 통한 수동 플레이 검증은 별개입니다.

성장 크기 45/30/25%, 연쇄 55% 등은 임시 밸런스입니다. 상세 규칙은
스킬의 references/RULES_KO.md를 확인하세요. 원본 첨부 기획의 교통·경제 전체를
구현한 프로젝트는 아닙니다.

## 중형 주거 건물 · 승인된 맨션 2종

4×4 주거 부지의 레벨 2 이상 성장에 아래 두 외관을 연결했습니다.

- `mansion-a-4x4-4f`: 벽돌형 맨션 · 지상 4층
- `mansion-b-4x4-4f`: 모던형 맨션 · 지상 4층

정의는 assets/buildings/catalog.json에 있습니다. 최초 해당 크기로 성장할 때
같은 가중치로 하나를 고르고, 같은 크기의 추가 성장에서는 외관을 유지합니다.
외관용 난수는 성장용 난수와 분리하여 기존 크기 추첨·연쇄 확률에 영향을 주지 않습니다.
2×2·8×8 및 상업·공업은 현재 기존 단순 모델을 사용합니다. 신축은 계속 2×2입니다.
층수 4와 게임 성장 레벨은 별개입니다.

900px 원본 PNG를 실제 격자 폭과 바닥 피벗에 맞춰 표시하며, 투명 여백은 선택되지 않습니다.
선택 정보에 중형 주거·외관 이름·층수를 표시합니다. 같은 PNG는 캐시하여 재사용합니다.
편집 가능한 원본은 ../assets/mansion-study에 보존합니다.

새 체크아웃에서는 Godot 편집기로 프로젝트를 한 번 열거나 리소스를 먼저 가져오세요.

```sh
godot --headless --editor --import --path cities_do
godot --headless --path cities_do --script tests/test_building_assets.gd
```


## 도로 주변 구획과 큰 맵

`core/zoning_grid.gd`는 32×32 청크에 드러난 구획만 보관하고 화면 내 청크만 조회합니다.
빈 지도는 전체 칸 배열을 만들지 않습니다. 일반도로 양쪽 8칸 범위만 표시하며
도로가 겹친 칸은 제거합니다. 도로 추가 시 전체 맵 대신 경로 주변 후보만 계산합니다.
고속도로는 구획 접근권을 주지 않습니다. 건물의 일반도로 접근 거리는 여전히 2.5칸입니다.

도로 구간별 로컬 좌표에서 반듯한 칸을 생성합니다. 사선·꺾임·곡선에서도 구획 깊이는
해당 블록 진행 방향에 수직입니다. 블록 사이 자동 합필은 미구현입니다. PNG 도로 시안과 실제 연속 좌표
벡터 도로는 표현 방식이 다르며 동일 폭·팔레트를 기준으로 연결했습니다.

```sh
godot --headless --path cities_do --script tests/test_roads_zoning.gd
```

1024×1024 빈 지도와 짧은 도로 생성은 검사했으나, 많은 도로·시민·건물을 채운
지도와 프레임 성능은 검증하지 않았습니다. 대규모 도로 인덱스·렌더링 캐시·구획 계산
분할 작업은 후속 최적화 항목입니다.

## 실제 게임 주거 10종 전시

건설 화면의 **주거 건물 10종 전시** 버튼을 누르거나 다음 장면을 직접 실행합니다.

```sh
godot --path cities_do residential_showcase.tscn
```

소형 4종·중형 맨션 2종·대형 4종을 같은 100×100 지도와 같은 축척으로,
왕복 4차로 도로를 따라 나란히 배치합니다. 전시 배치는 일반 건설과 별개의 완성
건물 배치 함수지만, 경계·겹침·도로 접근 검사는 동일한 모델을 사용합니다.
화면의 01~10 번호는 왼쪽 건물 목록과 대응합니다.

- 건물 클릭: 이름·분류·부지·층수 표시.
- 전체 건물 한눈에 보기 / 소형·중형 확대 / 대형 주거 확대.
- 휠 확대·축소, 가운데 버튼 드래그 이동.
- 건설 화면으로 돌아가기: 들어오기 전 도시 데이터와 카메라 위치 복원.
- 일반 건설 화면은 계속 빈 지도로 시작합니다.

새 8종은 현재 전시용 카탈로그(`growth_enabled: false`)로 연결했습니다.
기존 중형 2종의 성장 조건을 유지하며, 소형/중형/대형이 같은 4×4 부지에
등장하는 성장·밀도 조건은 별도 밸런스 작업으로 남겨 두었습니다.

실제 게임 화면은 ../docs/screenshots/residential-showcase.png,
residential-showcase-small-medium.png, residential-showcase-large.png에 있습니다.
Blender 비교판 합성이 아닌 Godot GL Compatibility 뷰포트의 직접 캡처입니다.

그래픽 환경에서 뷰포트를 저장하는 명령(절대 출력 경로를 사용):

```sh
godot --path cities_do --resolution 2560x1100 residential_showcase.tscn -- \
  --capture-showcase=/absolute/path/showcase.png
```

`--showcase-focus=small` 또는 `--showcase-focus=large`를 사용자 인자로 추가하면
해당 구간으로 확대해서 저장합니다. 캡처 후 프로세스가 종료됩니다.
headless dummy 렌더러는 이미지 캡처에 사용할 수 없으므로 실제 그래픽 디스플레이가 필요합니다.


## 도로에서 직각으로 나오는 구획

건설 화면의 **도로 직각 구획 예시** 버튼 또는 다음 장면을 실행하세요.

```sh
godot --path cities_do road_parcel_demo.tscn
```

[실제 게임 캡처](../docs/screenshots/road-perpendicular-parcels.png)의 우측 아래는
같은 데이터를 위에서 본 평면도입니다. 아이소메트릭 화면상의 각도와 지도 위 90도는
다릅니다. 현재 규칙은 다음과 같습니다.

1. 각 블록의 u축은 도로 진행 방향, v축은 양옆으로 나가는 수직 방향입니다.
   칸은 모두 지도 위 4m×4m 정사각형이며 마름모/사다리꼴로 변형하지 않습니다.
2. 도로 전체를 직선·곡선으로 강제 분류하지 않습니다. 구획 생성 시 짧은 직선
   블록을 만들고, 블록 양끝을 이은 기준선으로 접선 방향을 근사합니다.
3. 기본 블록 최대 길이는 8칸(32m), 각 경로 샘플 방향은 기준선에서 ±10도 이내,
   경로와 기준선의 최대 벌어짐은 0.25칸(1m)입니다. 한계를 넘으면 새 블록입니다.
   모두 growth_config.gd의 임시 튜닝 값이며 아직 최종 밸런스가 아닙니다.
4. 도로가 꺾이면 블록 방향도 바뀝니다. 곡선 안쪽이나 교차로에서 겹치는 칸,
   도로를 침범하는 칸, 지도 밖으로 나가는 칸은 생성하지 않습니다. 겹치는 구획은
   먼저 지은 도로/앞선 블록 순서가 우선입니다. 남은 틈은 빈 땅으로 둡니다.
5. UI 신축은 선택한 블록 안에서 2×2로 스냅합니다. 성장도 같은 블록 안에서
   2×2·4×4·8×8을 검사하며 기존 건물을 휘거나 자동 철거하지 않습니다.
6. 건설·충돌·선택·공유 변 인접 판정은 회전된 부지 다각형을 사용합니다.
   기존 월드축 부지 API는 예전 전시/수동 배치용으로 보존했습니다.
7. 같은 방향의 입력 점을 많이 찍어도 아주 짧은 블록이 남발되지 않도록 묶으며,
   긴 직선은 정확히 8칸에서 분할해 8×8 부지 가능성을 유지합니다.

**현재 외관 한계:** 기존 주거 PNG는 고정 시점 이미지입니다. 맞지 않는 방향의
PNG를 회전·찌그러뜨려서 붙이지 않고, 새 회전 부지는 방향에 맞춘 임시 입체
건물로 표시합니다. 외관이 지정되면 층수에 맞는 높이를 반영하지만 실제 외관
연결에는 방향별 이미지나 3D 렌더러가 추가로 필요합니다. 예전 주거 10종 전시의
수동 배치 건물을 도로 쪽으로 자동 이동/회전하지 않습니다.

구획은 32×32 희소 버킷에 저장합니다. 현재는 도로 추가 때 기존 도로 주변 블록을
재구성하며, 전체 1024×1024 칸을 스캔하지 않습니다. 큰 도시의 증분 갱신·도로
공간 인덱스 최적화는 미완료입니다. 큰 좌표에서 경계 접촉이 충돌로 오인되지 않도록
작은 부동소수점 허용 오차를 적용하며 1024 좌표에서 8×8 검사도 수행합니다.
