사용자 요청대로 **상수관과 하수관을 한 번에 설치**한다. 푸른 관은 상수, 갈색 관은 하수다.
이동하는 푸른 원과 갈색 원은 각각의 관을 따라 흐르며, 원의 윤곽이 부드럽게 늘었다
줄고 출렁이도록 했다. 원의 변형은 표시 효과이며 유체 입자의 실제 배송을 계산하지 않는다.

## 실행과 조작

저장소 최신 main을 받아 Godot 4.6.3에서 `cities_do/project.godot`을 연다.
일반 건설 화면의 **상하수도** 버튼 → **취수장 배치 / 하수처리장 배치**로 일반도로 옆에
시험 시설을 설치한다. **상하수관 함께 · 드래그**로 시설 접속점, 이웃 포트 또는 기존 접속점에서
관을 그린다. 한 경로가 두 관의 공통 건설 데이터이며 미리보기·확정·철거가 항상 함께 적용된다.
도로·건물·전력선과 겹칠 수 있고 지하 깊이는 지정하지 않는다. 끝에 별도 시설이 필요 없다.
시설 선택 후 m³/일 용량 조정, 함께 철거, 범위 표시, 흐름 표시 끄기, 흐름만 일시정지가 가능하다.
전력 탭과 상하수도 탭은 번갈아 열리며, 닫아도 공급과 계량은 계속된다.

**상하수도 실습 도시** 버튼은 내 도시·카메라를 보관하고 실제 공급 엔진을 사용하는 시험장으로
전환한다. 내부 급수·처리 / 상수 잉여 수출 / 상수 수입·하수 외부 위탁 / 관로 단선을 비교하고
**내 도시로 돌아가기**로 복귀한다. CLI: `godot --path cities_do water_demo.tscn`.
기존 ZIP들은 이전 작업 시점의 스냅샷이므로 이 기능은 최신 main을 사용한다.

## 공급·처리 규칙

- 전력망과 같은 **반경 64m, 경로 길이 기준 접속점 32m**, 1칸=4m다.
- 짧은 끝 구간·꺾임에는 연결용 접점을 두되 추가 범위 원을 만들지 않는다.
  시설 접속점도 공급/수거 범위의 기준이다. 단순 교차만으로 접속하지 않고 실제 접점에 연결한다.
- 연결된 같은 계통의 대상에게 같은 시뮬레이션 갱신에서 공급한다.
  푸른 원이 도착하기 전부터 급수되며, 갈색 원이 처리장에 닿을 때까지 처리 판정을 기다리지 않는다.
- 물 공급은 내부 취수량을 우선 사용하고 부족하면 연결 이웃에서 수입한다.
  남는 물은 이웃이 연결돼 있을 때 수출하며, 연결이 없으면 추가 생산하지 않는 것으로 취급한다.
- 하수는 **실제 급수량의 80%**를 발생량으로 사용하는 시험 규칙이다.
  내부 처리장 용량을 우선 쓰고 나머지는 연결 이웃에 처리 위탁한다.
  이웃도 없고 처리 용량도 부족하면 **미처리 m³/일**과 건물의 처리 비율을 표시한다.
- 상수 공급과 하수 처리 상태를 분리했다. 하수 부족을 이유로 정상 상수를 임의로 끊지 않는다.
  처리수는 상수 생산량에 합산하지 않는다. 오염·슬러지·재이용·역류·미처리 하수의 장기 누적은 후속이다.
- 부족 시 같은 계통의 모든 대상에 같은 비율로 나눈다. 겹치는 범위에 있어도 수요는 한 번만 센다.
  서로 분리된 관망이 겹치면 가장 가까운 접속점을 사용하며, 다른 계통의 여유 용량을 찾아
  재배정하는 최적화는 없다. 전력망과 관망은 겹쳐도 연결 데이터/서비스가 섞이지 않는다.
- 이웃 포트는 네 변 중앙이다. 지도 가장자리를 따라 들어온 관도 실제 포트에 닿으면
  상수/하수 두 지역 교류 채널을 함께 표시하고, 마지막 관을 끊으면 둘 다 해제한다.

## 흐름과 실제 물량의 분리

푸른 원: 취수장·수입 이웃 → 건물 접속점, 잉여 수출은 이웃 포트까지.
갈색 원: 건물 접속점 → 하수처리장·위탁 이웃.
공급/처리 경로 끝에서 원이 사라진다. 건물의 반경 내 연결은 접속점으로 표현한다.
여러 시설이 있으면 원은 유효 방향을 보여주며 개별 관의 정확한 유량 비중을 표현하지 않는다.
표시 경로는 최대 채널별 128개지만 실제 공급 대상 수를 제한하는 값은 아니다.

원은 약 1.1초 간격으로 나오고 윤곽의 3개 파동과 가로/세로 신축을 조합한다.
속도·개수·윤곽·숨김·표시만 정지는 공급·처리·교역량을 바꾸지 않는다.
물량(m³)=공급/처리율(m³/게임일)×경과 게임일. 현재는 전력 시험 시간과 같이
현실 1초=게임 1초, 86,400초=1일이다. 하루 가속/달력 정책은 아직 미정이다.
조회는 물량을 누적하지 않고 `advance_water(days)`만 계량한다.
사용자 위임으로 **수도 거래단가와 실제 물량 정산을 적용**했다.
[단가 표·수정할 JSON·정산 규칙](WATER_TARIFFS_KO.md)을 확인한다. 전기 단가를 물에 전용하지 않았다.
수도 계약한도·수압·지형 고저·관경별 운송 상한·손실은 아직 구현하지 않았다.

## 시험 수치와 가격·용량 제안

취수장/처리장은 2×2 임시 블록 외관이다. 완성된 시설 애셋이나 확정 부지 크기가 아니다.
용량 입력 기본값 1,000m³/일은 두 시험 시설에서 조정할 수 있다.
실습장은 건물 6채×40=240m³/일, 하수 192m³/일이며 실제 인구에 기반한 값이 아니다.
일반 도시의 2×2 1단계 상수 수요는 주거 1.6 / 상업 0.15 / 공업 0.30m³/일을
면적·단계에 비례시킨 임시 부하다. 인구/종사자 기반 수요는 후속 구현이다.

기존 [시설 가격](PRICE_PROPOSALS_KO.md)과 [용량 제안](CAPACITY_PROPOSALS_KO.md)을 바탕으로 다음을 제안한다.
아래 수치는 **승인 대기**이며 실제 건설비·유지비·시설 전력 소비·관 용량 제한으로 적용하지 않았다.

| 항목 | 건설비 doth | 유지비 doth/비교월 | 용량/생산 제안 | 자체 전력 제안 |
|---|---:|---:|---|---:|
| 상하수관 한 쌍 8m | 36 (상수 16+하수 20) | 2 (각 1) | 각 관 5,000m³/일 상한 | 펌프 시설에서 별도 |
| 취수장 | 8,000 | 120 | 1,000m³/일 공급 | 20kW |
| 하수처리장 | 18,000 | 250 | 2,400m³/일 처리 | 60kW |

한 쌍의 가격은 두 서비스의 기존 제안가 합이다. 지중 전력선 8m 20doth 제안과 비교해
80% 비싸지만 두 관을 함께 제공한다. 공유 굴착 할인은 향후 조정 가능하다.
물 시설이 관 상한보다 작으면 시설이 병목이며 직렬 관 수만큼 용량을 더하지 않는다.
취수장 1개+처리장 1개+두 관 200m라면 **26,900doth**로 시작 자금 50,000의 53.8%,
잔액 23,100doth, 비교월 유지비 420doth 제안이다. 취수장 단독은 시작 자금의 16%,
처리장 단독은 36%, 두 관 8m는 0.072%다. 비교월은 기존 가격표와 같은 검토 단위이며
이번 작업이 월간 달력이나 자동 시설 요금 정산을 구현한 것은 아니다.

취수장의 수원 배치 조건, 펌프 전원 필요성, 실제 공공시설 전력 부하, 오염 정화율 및
연료/운영비는 후속이다. 지금은 기능을 확인할 수 있는 시험 시설이며 무한 수원·무료 운영을
최종 경제 규칙으로 확정한 것이 아니다.

## 코드·재현·검사

- `core/water_grid.gd`: 한 쌍의 연결 그래프, 상수/하수 분리 수급, 외부 교류, 체적 계량.
  기존 `power_grid.gd`에서 검증한 미터 단위 경로 샘플·그래프·경로 찾기만 재사용한다.
  전력 공급 계산/전기 단가/자금 정산은 호출하지 않는다.
- `core/water_flow.gd`: 순수 표시 위치·푸른/갈색 구분·출렁이는 원 윤곽.
- `core/water_overlay.gd`: 두 관의 미리보기/건설/철거, 시험 시설·범위·유체 표시 UI.
- `core/city_model.gd`, `main.gd`: 건물 상태, 시설 충돌, 실제 시간 계량, 건설 화면 통합.
- `water_demo.gd/.tscn`: 조작 가능한 실제 모델 시험장, `--record-water=<폴더>`로 12초/8fps 캡처.
- `tools/capture_water_main.gd`: 실제 일반 건설 화면 캡처용 SceneTree 스크립트.

Godot 4.6.3에서 요금 포함 전용 검사 **80/80**, 전체 **12개 검사 스크립트 통과**.
[결과 JSON](water-validation/results.json)과 [검사 로그](water-validation/)를 함께 보존했다.
기하/동시 공급·처리/병목/삭제/외부 포트/실제 드래그/탭 전환/체적 계량/30·60 갱신 동등성/
흐름 방향·소멸·표시 독립성/실습 버튼을 검사했다. 실제 물리 유체 해석을 검증한 것은 아니다.

```sh
python tools/validate_water_update.py
godot --headless --path cities_do --script tests/test_water.gd
godot --path cities_do --resolution 1600x1000 water_demo.tscn -- --record-water=/tmp/water-frames
python tools/build_water_evidence.py --frames /tmp/water-frames
godot --path cities_do --script ../tools/capture_water_main.gd -- /tmp/water-main.png
```

마지막 명령의 스크립트는 저장소의 절대 경로로 지정하거나 `--script ../tools/capture_water_main.gd`로
지정한다(도구 폴더는 Godot 프로젝트 밖). 제한 환경은 writable XDG 경로를 사용한다.
화면/GIF는 Xvfb+Mesa OpenGL의 실제 Godot 뷰포트에서 캡처했다. 확대 GIF는 실제 장면의
관로 접점 부위를 잘라 확대했으며, HTML/생성형 시안을 작동 게임으로 제시하지 않았다.
