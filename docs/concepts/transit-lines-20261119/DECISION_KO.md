## 공통 규칙 (세 안 모두)

- 화면 규칙
  - 글자는 18px 이상이다(시안 CSS 최소 18px). 값과 숫자는 오른쪽 정렬이다.
  - 팔레트는 #142b37 / #38515e / #edf4f5 / #36b7ff다. 선택은 파란 실선과 배경, 키보드 포커스는 밝은 점선이다(캡처의 '정류장 추가', '완료').
  - 창 안에 설명 문구가 없다. 이름, 실제 값, 버튼만 있다.
  - 서체는 숫자·영문 Open Sans SemiBold(파일에 내장), 한글 맑은 고딕이다.
- 이름
  - 노선에 이름·색 필드가 없어 '종류 + 노선 id'로 적었다(예: 철도 1).
  - 정류장은 시설 이름('기차역')과 순서 번호로 적고, 같은 번호를 지도 표식에 붙였다.
- 종류 탭은 버스 / 철도 / 지하철 / 화물이다. 옆 숫자는 그 종류의 노선 수다.
- 지도 강조: 고른 노선의 실제 운행 경로를 파란 선으로, 정류장을 순서 번호 원으로 그린다. 창이 열릴 때 그 노선이 가려지지 않는 쪽으로 지도를 옮긴 상태로 그렸다.
- 정류장 편집
  - 추가: '정류장 추가'를 누르고 지도에서 같은 종류 정류장을 클릭한다.
  - 삭제는 ✕, 순서 바꾸기는 ▲▼(C는 ◀▶)다.
  - 정류장 목록이 바뀌면 경로를 다시 계산한다(`update_transit_line`). 실패하면 기존 실패 문구를 기존 짧은 피드백 자리에 그대로 쓴다(예: "종류가 같은 정류장을 선택하세요").
- 시간 단위: **게임 시계의 '분'**으로 보여 준다.
  - 설정 값은 시뮬레이션 초(1배속 현실 초)다. 게임 1시간이 150초이므로 게임 1분은 2.5초다.
  - 배차 간격 기본 60초 = 24분, 정차 시간 기본 5초 = 2분이다. 예시 노선 '철도 4'의 40분은 100초다.
  - 슬라이더 범위(제안): 배차 4~120분(10~300초), 4분 단위. 정차 1~10분(2.5~25초), 1분 단위.
  - 코드의 제한은 '1초 이상'뿐이다(`city_model.gd` `_set_transit_schedule`). 정류장 목록이 같으면 두 값만 바뀌고 경로와 차량은 그대로다.
- 차량: 노선마다 1대로 고정이다(`transit_operation_config.json`). 입력칸 없이 값만 둔다. 열차는 '1편성', 버스는 '1대'로 적는다.

### 운행 정보에 쓴 실제 값

| 화면 항목 | 데이터 | 집계 단위 |
|---|---|---|
| 상태 | `transit_state.lines[id].status`: running 운행 중 / dwelling 정차 중 / waiting 대기 / blocked 막힘 | 노선 |
| 출발 | `transit_state.lines[id].departures`: 첫 정류장을 떠난 횟수 | 노선 |
| 다음 정류장 | 열차는 `trains[id].next_stop`. 버스는 `stop_index`가 있고, 뜻(다음/현재)은 구현 때 확인한다. | 차량(노선당 1대) |
| 길이 | 경로 `plan.length`(m). 캡처 노선은 1,013 m다. | 노선 |

- 버스 노선에는 정차 횟수 `stops_served`도 있다. 시안의 예시는 철도 노선이라 넣지 않았다.

### 대기 승객 · 탑승 인원 조사 결과

- 승객 수를 뜻하는 대기·탑승 값은 지금 코드에 없다. 노선 단위로도 정류장 단위로도 집계하지 않는다.
  - `transit_operations.gd`의 `waiting`은 차량이 선로가 비기를 기다리는 상태 문자열이다. occupancy는 선로 점유(예약)다.
  - `scheduled_bus_simulation.gd`의 `waiting`, `occupancy`는 도로 위 차량의 대기열과 점유다.
  - 차량에는 정원이나 탑승 인원 필드가 없다.
- 승객은 통근 흐름(flows) 단위로만 있다. 흐름은 인원(count), 수단(mode), 방향, 경로 구간(legs)을 가진다.
  - 경로 그래프의 노선 구간에는 `line_id`, `from_stop`, `to_stop`이 들어간다(`transit_commuting.gd` 70행).
  - 그래서 노선별·정류장별 '하루 통근 이용 인원'은 흐름을 더하는 새 집계로 만들 수 있다.
  - 순간 대기 승객과 차내 인원은 승하차 시뮬레이션이 있어야 한다.
- 시안에는 '대기 승객 —', '탑승 인원 —'을 '새 데이터 필요' 점선 상자에만 두었다. 가짜 수치는 없다.

### 지금 없어서 코드가 필요한 것

- 운행 켜기/끄기: 노선에 `enabled`가 있고 만들 때 true다. 읽는 곳은 통근 경로 계산(`transit_commuting.gd` 40행)뿐이다. 값을 바꾸는 함수가 없고, 차량 운행(`transit_operations.gd`)은 이 값을 보지 않는다.
- 노선 이름·색, 요금, 유지비 필드는 없다.

## 장면 2 — 새 노선을 만드는 중 (추천안 B, `s2-B.png`)

장면: 기차역 2곳을 고르고 세 번째 역 위에 커서를 올린 순간이다.

- 시작: 패널의 '새 노선' 버튼 또는 교통 트레이의 '노선' 도구. 둘 다 같은 상태로 들어간다.
- 지도에서 정류장을 클릭할 때마다 패널의 '새 노선' 칸에 번호 줄이 생기고, 같은 번호 원이 지도에 붙는다.
- 다음 차례는 점선이다. 패널의 빈 칸 ③과 지도 커서 아래의 점선 원 ③이 짝이다.
- 첫 정류장을 고르면 종류가 정해지고 다른 종류 탭이 흐려진다. 화물 노선은 화물 탭에서 '새 노선'을 눌러 시작한다.
- 줄의 ✕로 고른 정류장을 뺀다.
- '완료'를 누르면 노선이 생기고(`create_transit_line`) 그 노선이 펼쳐진 장면 1이 된다. 정류장이 2곳 이상일 때 켜진다. '취소'나 Esc, 오른쪽 클릭으로 버린다.
- 지금의 '첫 정류장을 다시 클릭하면 완료'는 그대로 둔다.
- 고르는 중에는 경로 선을 그리지 않았다. 지금 코드가 완료할 때만 경로를 계산하고 검증하기 때문이다(`transit_line_tool.gd` `draw_preview`).
- 안내 문구는 넣지 않았다.
