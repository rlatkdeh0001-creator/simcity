# 지중 전력망 실제 도입 · 2026-11-02

사용자 승인으로 건설 화면에 통합했다. [실제 실행 GIF](screenshots/power-game-running.gif) · [수출 화면](screenshots/power-game-export.png) · [검사 결과](power-validation/results.json)
기존 concepts 폴더는 도입 전 시안 기록이며, 이 문서는 현재 코드의 동작을 설명한다.

## 사용법

저장소 최신 main을 받아 Godot 4.6.3에서 `cities_do/project.godot`을 연다.
건설 화면의 **전력** 버튼에서 발전소를 일반도로 옆에 배치한 다음, 파란 탭 또는
이웃 접속점에서 전력선을 드래그한다. 기존 접속점에서 분기도 가능하다.
선은 도로·건물과 겹칠 수 있으며 지하 깊이 설정은 없다. 끝에 별도 시설이 필요 없다.
발전소 선택 후 출력을 조정하거나 선택 건물의 시험용 부하를 조정할 수 있다.
선/발전소 철거 도구와 범위·흐름 표시 토글도 있다.

**전력 실습 도시** 버튼은 도시와 카메라를 보관하고 시험장으로 전환한다.
내부 공급, 잉여 수출, 부족 수입, 발전 정지·단선 버튼을 누른 뒤 내 도시로 돌아올 수 있다.
직접 실행은 `godot --path cities_do power_demo.tscn`이다.

## 공급과 표시

- 1칸=4m. 공급 반경은 **64m**, 경로 길이 기준 공급점 간격은 **32m**다.
- 끝의 짧은 구간과 꺾임에는 경로 연결용 접점이 생기지만 추가 공급 원을 생성하지 않는다.
  현재 스냅은 이런 연결용 접점도 대상으로 한다. 단순 선 교차는 자동 접속하지 않으며,
  같은 접점에 닿거나 스냅해야 계통이 연결된다.
- 발전소·이웃 포트도 실제 선을 연결해야 공급한다. 이웃 포트는 지도 네 변 중앙에 있다.
- 연결 계통마다 수요를 한 번씩 집계하고, 충분하면 모든 대상에 같은 갱신에서 공급한다.
  부족하고 수입도 불가능하면 해당 계통의 대상에 같은 비율로 배분한다.
- 내부 수요 우선, 부족 시 가장 싼 연결 이웃에서 수입, 잉여는 가장 비싸게 사는 이웃에 수출한다.
  계약한도는 사용자 요청대로 **적용하지 않았다**. 선로 용량/손실도 아직 없다.
- 하얀 원은 순수 표시다. 내부 말단/수출 경계에서 사라지며 수입은 이웃에서 도시 방향이다.
  도착·속도·개수·표시 끄기·표시만 일시정지는 공급이나 요금을 바꾸지 않는다.
- 서로 분리된 계통의 공급 원이 겹치면 가장 가까운 유효 공급점에 건물을 한 번만 배정한다.
  다른 계통의 여유 전력을 재배분하는 최적화는 없다. 분리 계통끼리는 수입/수출이 각각 가능하다.

## 실제 적용 거래단가

| 상대 | 수입 doth/kWh | 수출 doth/kWh |
|---|---:|---:|
| 엄청 발전한 마을 | 0.0024 | 0.0010 |
| 발전한 마을 | 0.0027 | 0.0012 |
| 비슷한 마을 A/B | 0.0030 | 0.0015 |

전력량(kWh)=거래전력(kW)×경과시간(h), 거래액=전력량×단가다.
현재 시험 시간은 **현실 1초=게임 1초**다. 달력/가속 시간 정책은 별도 미정이다.
소수 거래액은 누적하고 정수 doth만 도시 자금에 정산하며 나머지는 이월한다.
잔액이 부족하면 구매 가능한 만큼만 수입한다. 자동 부채는 발생시키지 않는다.
예: 발전한 마을로 60kW를 1게임시간 수출하면 60kWh, 0.072doth를 적립한다.
이는 원이 흘러간 횟수와 무관하다.

## 임시 수치와 미완료 범위

발전소는 **2×2 임시 블록 외관**이고 기본 300kW는 조정 가능한 시험값이다.
발전소 종류별 최종 애셋·발전량·연료/운영비는 아직 도입하지 않았다.
실제 인구 엔진이 없으므로 주거/상업/공업의 2×2 1단계 기본 부하는 각각
1.6/1.5/3.0kW를 면적과 단계에 비례시킨 임시값이며, 실습장은 건물마다 40kW로 지정한다.
전력 상태는 `has_power`와 `power_ratio`로 제공한다. 이 작업에서 전체 성장·세금 엔진을 완성하지 않았다.

[시설 가격](PRICE_PROPOSALS_KO.md)과 [용량](CAPACITY_PROPOSALS_KO.md)의 미승인 제안은
실제 공사비/유지비로 차감하지 않는다. 따라서 현재 발전·수출의 장기 경제 밸런스는 미완성이다.
기존 `add_external_link("power", ...)`는 외부 교류 표시용 API이고 실제 공급은
`city.power.add_wire(...)`로 연결한 전력망을 사용한다. 철도·지하철·상하수도 전체 공급 구현을 뜻하지 않는다.

## 구현과 검사

- `core/power_grid.gd`: 경로 샘플·연결 성분·공급·교역 계산. `solve`는 조회이며 정산하지 않는다.
- `core/city_model.gd`: 건설 충돌, 건물 수요·상태, `advance_power(hours)` 전력량/자금 정산.
- `core/power_flow.gd`: 상태를 읽는 순수 표시 위치 계산.
- `core/power_overlay.gd`, `main.gd`: 실제 건설 도구·UI·매 갱신 계량.
- `power_demo.gd/.tscn`: 실제 렌더러·실제 모델을 이용한 조작 가능한 시험장.

Godot 4.6.3에서 `tests/test_*.gd` 전체 **11개 스크립트 통과**.
그중 `test_power.gd` **41/41**: 거리·간격, 분기/꺾임, 중복 수요, 동시 공급,
부족 배분, 철거, 발전도별 단가, 최적 이웃, 계약한도 미적용, kWh와 소수 이월,
30/60 갱신 동등성, 잔액 제한, 원의 도착 전 공급, 표시 독립성, 실제 UI 드래그를 검사했다.
명령은 `godot --headless --path cities_do --script tests/test_power.gd`.
제한 환경은 writable XDG_DATA_HOME/CONFIG_HOME/CACHE_HOME을 지정한다.
[각 검사 로그](power-validation/)와 results.json을 보존했다.

화면과 GIF는 Xvfb + Mesa llvmpipe OpenGL에서 Godot의 실제 뷰포트를 캡처했다.
GIF는 `--record-power=<폴더>`로 약 24초 동안 내부 공급→수출→수입 장면을 기록한 뒤
Pillow로 변환했다. headless 검사나 HTML 시안 캡처를 게임 화면으로 제시한 것이 아니다.
