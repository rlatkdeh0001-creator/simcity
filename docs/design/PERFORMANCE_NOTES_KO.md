# 성능 기법 메모 (기획 참고, 2026-11-11)

출처: 커뮤니티 스킬 `godot-performance-optimization`(thedivergentai/game-dev-agentic-skills) 검토 + Godot 공식 성능 문서. 스킬 자체는 설치하지 않고 필요한 기법만 지시서에 넣는다.
게임은 아이소메트릭 시점이지만 내부는 3D(GLB + 고정 카메라)라 3D 기법이 적용된다.

## 원칙

- **측정 먼저**: 최적화 전에 Godot 프로파일러(시간·메모리·GPU)로 병목을 확인하고 수치를 기록. 추측 최적화 금지.

## 우리 게임에 쓸 기법

| 기법 | 적용 대상 | 시점 |
|---|---|---|
| 오브젝트 풀링(삭제·생성 대신 재사용) | 차량(② 화면 샘플링 표시), 시민 표시 | 차량 표시 작업 |
| 화면 밖 처리 끄기 | 화면 밖 차량·애니메이션 | 차량 표시 작업 |
| MultiMesh 인스턴싱(+구역별 분할로 컬링 유지) | 같은 건물·나무·가로등 다량 | 10km 맵 |
| 거리별 표시 범위·LOD | 멀리 있는 건물·차량 단순화/숨김 | 10km 맵 |
| 청크(구역) 단위 관리 | 맵 2,500×2,500칸 | 10km 맵 |
| WorkerThreadPool(무거운 계산을 별도 스레드) | 경제 정산, 성장 판정, 통근 경로 계산 | 경제 순환 A 이후 |
| 경로 계산 분산(한 프레임에 몰지 않기) | 시민 통근·서비스 차량 경로 | 통근(C) 단계 |
| RenderingServer 직접 사용 | 노드 수가 병목일 때만 | 측정 후 |
| VRAM 압축(데스크톱 S3TC/BPTC) | 건물 텍스처 | 애셋 많아질 때 |

## 해당 없음

2D 전용 기법, 물리 레이캐스트, 모바일 대응.

## 시뮬레이션 갱신 주기 (사용자 확정 2026-11-14)

배경: 시민 100명 데모에서 시민 0명·시뮬레이션 정지 상태도 약 23FPS(docs/citizens-100-demo/fps.json). 코드 점검 의심 지점: main.gd `_draw()` 매 프레임 전체 재그리기(화면 밖 포함), 건물·차량 매 프레임 정렬, 전기·수도 매 프레임 전체 계산, 수도 오버레이 탭 닫혀도 재그리기, 도로 그리기 중 매 프레임 add_road 검사.

- **성장 판정: 게임 1시간마다** (1배속 현실 2.5초, 3배속 약 0.8초). 현재 2초(게임 48분)에서 변경. 연속 유지 판정이 하루 24회라 정확도 충분.
- **전기·수도: 게임 1시간마다 1회 계산**, 그 1시간의 수지(±)로 요금 정산(합계는 매 프레임 계산과 같게).
  - 건물·발전소·전선·배관 추가/철거는 '변경 표시'만 해 두고 **다음 정각 계산에서 반영**(1배속 최대 2.5초 지연).
  - 전기·수도 화면 숫자도 같은 정각에 갱신. 그리기는 해당 탭이 열렸을 때만.
- **화면 밖 건물**: 그리지 않음. 시뮬레이션(성장·입주·출퇴근)은 화면과 무관하게 계속.

## 그리기 층 분리 (제안 2026-11-14, 사용자 질문 "차량만 그리면 되는 거 아닌가")

- 현재: main.gd `_draw()`가 `screen()`(카메라 위치·줌)으로 변환한 좌표를 직접 그림 → 카메라를 움직이거나 차가 한 칸 움직일 때마다 맵 전체를 다시 그림.
- **고정 층**(지형·구역·도로·차선·횡단보도): 월드 좌표로 한 번만 그리고 저장. 다시 그리는 건 도로·구역이 바뀔 때만. 카메라 이동·줌은 층 전체의 변환(Camera2D/transform)만 바꿈 → 다시 그리기 없음.
- **움직이는 층**(차량·시민): 매 프레임. 화면 안의 것만.
- **건물**: 고정이지만 차·사람이 건물 뒤로 가려져야 하므로 고정 층에 굽지 않고, 건물마다 Sprite2D 노드로 두고 차·시민과 같은 깊이 정렬(y_sort)에 넣음 → 건물은 다시 그리지 않고 순서만 엔진이 처리.

## 시민·차량 표시 단계 (사용자 확정 2026-11-14)

- **화면 밖**: 그리지 않음. 걷기 프레임·방향 계산도 안 함.
- **화면 안, 멀리(줌 아웃)**: 점 1개(상의 색). 4층 합성 안 함.
- **화면 안, 가까이**: 4층 합성 + 걷기 동작.
- 화면 밖 시민은 매 프레임 위치를 옮기지 않고 '출발 시각·경로'만 보관 → 화면에 들어올 때 현재 위치를 계산해 그 자리에 표시(도착·출근 판정은 시각으로).
- 기존 규칙 유지: 시민은 1:1 계산, 화면 표시는 샘플링(VEHICLE_SPAWN_DESPAWN_KO 110~117행).
- **차량 예외 (사용자 확정 2026-11-14)**: 교통 체증은 플레이어가 보고 찾는 재미 → 차량은 화면 밖에서도 시간 건너뛰기 없이 실제로 이동·정체 계산, 줌 아웃해도 점으로 바꾸지 않고 차 그림 유지. 화면 밖 차는 그리기만 생략(안 보이므로 차이 없음). 표시 샘플링 비율은 기존대로 100건당 1대 유지(VEHICLE_SPAWN_DESPAWN 110행, 사용자 확정 2026-11-14 — 체감 확인 후 재검토).

## 구획 격자 (사용자 제보 2026-11-14: 구획 탭에서 렉 심함)

- 원인(코드 확인): main.gd `_draw()` 653~661행 — 화면 안 구획 칸마다 매 프레임 ① `zoning_grid.parcels_in()`로 칸 목록 다시 검색(칸마다 경계 계산), ② 채운 다각형 + 안티앨리어싱 외곽선 각각 그리기. 줌 아웃 시 화면 안 칸이 수천 개 → 수천 번 × 2.
- 해결: 구획 격자도 고정 층. 칸 색(지정 구역)·도로가 바뀔 때만 다시 그림. 외곽선은 칸마다 따로가 아니라 격자 선 묶음 하나로(또는 셰이더 격자). 너무 멀리 줌 아웃하면 외곽선 생략, 색만.
