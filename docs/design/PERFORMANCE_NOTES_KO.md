# 성능 기법 메모 (기획 참고, 2026-11-11)

출처: 커뮤니티 스킬 `godot-performance-optimization`(thedivergentai/game-dev-agentic-skills) 검토 + Godot 공식 성능 문서. 스킬 자체는 설치하지 않고 필요한 기법만 지시서에 넣는다.
게임은 아이소메트릭 시점이지만 내부는 3D(GLB + 고정 카메라)라 3D 기법이 적용된다.

## 원칙

- **측정 먼저**: 최적화 전에 Godot 프로파일러(시간·메모리·GPU)로 병목을 확인하고 수치를 기록. 추측 최적화 금지.

## 우리 게임에 쓸 기법

| 기법 | 적용 대상 | 시점 |
|---|---|---|
| 오브젝트 풀링(삭제·생성 대신 재사용) | 차량(② 화면 샘플링 표시), 시민 표시 | 차량 표시 작업 |
| 화면 밖 처리 끄기 | 화면 밖 차량·애니메이션 | 차량 표시 작업 |
| MultiMesh 인스턴싱(+구역별 분할로 컬링 유지) | 같은 건물·나무·가로등 다량 | 10km 맵 |
| 거리별 표시 범위·LOD | 멀리 있는 건물·차량 단순화/숨김 | 10km 맵 |
| 청크(구역) 단위 관리 | 맵 2,500×2,500칸 | 10km 맵 |
| WorkerThreadPool(무거운 계산을 별도 스레드) | 경제 정산, 성장 판정, 통근 경로 계산 | 경제 순환 A 이후 |
| 경로 계산 분산(한 프레임에 몰지 않기) | 시민 통근·서비스 차량 경로 | 통근(C) 단계 |
| RenderingServer 직접 사용 | 노드 수가 병목일 때만 | 측정 후 |
| VRAM 압축(데스크톱 S3TC/BPTC) | 건물 텍스처 | 애셋 많아질 때 |
