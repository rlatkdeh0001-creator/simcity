# 주민·사업장·물자·행복도 경제 순환 — 기획 명세 v2 (백로그 3번)

작성: 시티즈 클로드(기획). 상태: **제안(사용자 일부 확정, 나머지 승인 대기)**. 구현: 시티즈 지피티.
v1(단일 물품)은 폐기. 이 문서의 수치는 모두 임시 제안이며 승인 전에 실제 과금·밸런스로 확정하지 않는다.

## 0. 사용자 확정 사항 (2026-11-10)

1. 물자는 **식량, 석탄, 석유, 의료품, 가전, 사치품** 6종.
2. **이웃 마을 수입은 당연히 허용**한다(기존 네 이웃 마을 체계 사용).
3. **소득 없는 가구는 행복도가 낮아지고**, 계속 낮아지면 **변두리로 이사**, 거기서도 갈 곳이 없으면 **도시를 떠난다.**

## 1. 현재 보유 건물로 본 물자 매핑 (실제 코드·카탈로그 대조)

| 건물/요소 (현재 상태) | 물자와의 관계 |
|---|---|
| 주거 10종(실제 모델) + 가구/주민 | **소비처**: 식량(필수), 의료품, 가전, 사치품. 소득이 구매력 |
| 상업 구획(임시 블록, 전용 모델 없음) | **판매처**: 소비재 재고를 두고 주민에게 판매 |
| 공업 구획(임시 블록, 전용 모델 없음) | **생산처**: 업종별 소비재 생산 (아래 업종 속성) |
| 발전소(석탄 8,000 kW / 석유 16,000 kW 제안 있음) | **연료 소비처**: 석탄·석유 (§6 단계 B) |
| 병원·진료소·대형병원(모델만, 운영 미구현) | 장래 **의료품 소비처**. 이번엔 운영 미구현이므로 연결하지 않음 |
| 소방차·경찰차 등 차량(연료 L/일 제안) | 장래 석유 소비처 (후속) |
| 트럭 모델: 탱커·덤프·냉동·박스·플랫베드·컨테이너 | 2단계(물류 차량) 때 석유=탱커, 석탄=덤프, 식량·의료품=냉동/박스, 가전·사치품=박스·컨테이너로 연결 가능 |
| 이웃 4마을(엄청 발전/발전/비슷 A/B) + 도로 채널 | **수입처/수출처** (§5) |

중요한 한계: 건물 모델이 업종별로 있지 않다. **새 건물 모델을 만들지 않는다.** 업종은 데이터 속성으로 두고,
외형은 현재 임시 블록을 유지한다(구분이 필요하면 업종별 색 띠 같은 최소 표시만, 사용자 승인 후).
석탄·석유는 맵에 자원 지형·광산·유전이 없으므로 **당분간 100% 이웃 수입**이다.

## 2. 물자 정의 (제안)

| 물자 | 성격 | 주 소비처 | 국내 생산 | 임시 단위당 도매가 (doth) |
|---|---|---|---|---|
| 식량 | 필수 소비재 | 전 가구 | 공업(식품가공 업종) | 4 |
| 석탄 | 연료/원자재 | 석탄 발전소(단계 B), 공업 에너지(후속) | 불가(자원 없음) → 수입 | 3 |
| 석유 | 연료/원자재 | 석유 발전소(단계 B), 차량(후속) | 불가 → 수입 | 6 |
| 의료품 | 소비재 | 전 가구(소량), 병원(후속) | 공업(제약 업종) | 12 |
| 가전 | 내구 소비재 | 중간 소득 이상 가구 | 공업(전자 업종) | 25 |
| 사치품 | 고급 소비재 | 고소득 가구 | 공업(사치품 업종) | 60 |

단위는 추상 "단위"다(톤·개수 환산 없음). 물자 목록은 설정 파일(JSON)에서 읽어 추가/삭제가 쉽게 한다.

## 3. 상태 모델

모든 주체는 안정 ID를 가진다(저장 대비). 시 자금(city.funds)은 이번 단계에서 **증감하지 않는다**(세금은 백로그 4번).

| 주체 | 추가 필드 |
|---|---|
| Household | cash(소수 이월), income_today, needs_met{물자별 충족률}, **happiness(0~100)**, low_happiness_days, status(정상/변두리 이주 대기/이탈 예정) |
| Workplace(공업) | sector(업종), stock{물자}, production_today, wage_bill_today, balance |
| Workplace(상업) | sells[취급 물자], stock{물자}, stock_capacity, restock_request, revenue_today, balance |
| 도시 전체 | goods_ledger{물자: 생산, 소비, 수입, 수출, 재고}, 일일 보존 검산 |

**업종 부여**: 공업/상업 신축 허가 시 그 시점의 **미충족 수요가 가장 큰 물자**의 업종을 건물에 붙인다
(결정적 규칙, 동점은 고정 순서). 업종은 이후 변경하지 않는다. 한 상업 건물은 소비재 4종을 모두 취급(1단계 단순화).

## 4. 시간·정산 규칙

- 기존 고정 society 틱(현실 2초=게임 48초)과 city.clock 사용. 새 타이머 금지.
- 생산·판매·재고 이동은 틱 단위 비례 처리, **금전·행복도 정산은 게임일 경계(00:00) 1회.** 소수 잔액 이월.
- 정지/배속/큰 시간 점프에서 일 정산이 누락 없이 따라잡는다.

## 5. 물자 흐름과 이웃 마을 수입/수출 (제안)

1. **소비**: 가구는 하루 필요량을 소득 범위 안에서 구매(우선순위: 식량 → 의료품 → 가전 → 사치품).
   가전은 소득 중간 이상, 사치품은 고소득만 구매한다(소득 구간은 §7 표).
2. **판매/재고**: 상업 재고에서 구매, 재고 30% 이하에서 보충 요청. 보충은 ① 국내 공업 재고 → ② 부족분은 수입 순서.
3. **수입**: 도로 채널이 연결된 이웃(`exchange_available`, 도로 연결 기준)에서만 가능. 수입 단가 = 도매가 × 이웃 계수(§5-1) + 운송 프리미엄.
   수입 대금은 **상업/공업 사업장의 balance에서 지불**하는 민간 거래로 처리하며 시 자금은 건드리지 않는다(세금·관세는 4번 범위).
   이웃과 도로 연결이 없으면 수입 불가 → 부족분은 `unmet_need`로 쌓인다.
4. **수출**: 국내 공업 재고가 상업 보충 후 임계(예: 용량 80%) 이상이면 연결된 이웃에 수출해 balance를 늘린다(수출 단가는 도매가 × 낮은 계수).
5. 물량/요금은 모두 **상태·장부 계산**이다. 실제 트럭 이동은 2단계(§8). 하루 최대 거래량은 도로 채널 수 기준 상한 제안(채널당 N단위/일, N은 조정 값).

### 5-1. 이웃 마을별 교역 성향 (임시, 사용자 확정 필요)

| 이웃 | 잘 파는 물자(저렴, 계수 1.1) | 보통(계수 1.4) | 사는 물자(수출 단가 계수 0.9) |
|---|---|---|---|
| 엄청 발전한 마을 | 의료품, 가전, 사치품 | 식량 | 석탄·석유 제외, 식량 |
| 발전한 마을 | 가전, 의료품 | 식량, 사치품 | 식량 |
| 비슷한 마을 A | 식량, 석탄 | 석유, 의료품 | 가전 |
| 비슷한 마을 B | 식량, 석유 | 석탄, 의료품 | 가전 |

(이웃의 구체 재고 모델은 만들지 않고 무한 공급/수요로 단순화. 플레이어 성장에 따른 상대 수준 갱신은 기존 문서대로 미정.)

## 6. 석탄·석유의 쓰임 (단계 B, **발전 규칙 변경이므로 별도 승인 필요**)

- 현재 발전소는 연료 없이 정해진 출력을 낸다. 연료 의존을 넣으면 **석탄/석유 발전소의 출력이 연료 재고에 비례**하고
  연료가 없으면 출력 0이 된다(이웃 수입이 끊기면 정전 가능).
- 연료 소비 = 출력 kWh × 계수(제안: 석탄 0.4 단위/MWh, 석유 0.25 단위/MWh). 풍력·태양광·수력·원자력·소각 발전은 영향 없음.
- 기존 규칙 유지: **충분한 전력은 연결 대상에 동시 공급**, 흐름 원 표시는 공급과 무관(ELECTRICITY_RULES_KO.md).
- 가격 이중 청구 방지: CAPACITY_PROPOSALS_KO.md가 "연료 수입비를 별도 계산하면 유지비를 재조정"한다고 이미 명시 →
  연료분을 유지비에서 분리해 새 유지비를 제안하고 승인 후 적용.
- 이 단계는 설정 스위치(기본 꺼짐)로 도입해 기존 전력 테스트(41/41)가 깨지지 않게 하고, 켠 상태의 별도 테스트를 추가한다.

## 7. 임금·소득·소비 구간 (제안, 사용자 미확정)

| 학력 단계(0~4) | 일급 (doth/게임일) |
|---|---|
| 0 | 30 |
| 1 | 40 |
| 2 | 55 |
| 3 | 75 |
| 4 | 100 |

가구 소득 = 취업 구성원 일급 합. 1인당 필요량(/일): 식량 1.0, 의료품 0.1, 가전 0.05(소득 중간 이상), 사치품 0.02(고소득).
소득 구간(가구 일소득): 저 <80, 중 80~179, 고 ≥180 (예시 값; 가구 구성별 보정은 지피티가 검산 후 제안).
공업 생산 = 취업자 수 × 학력 가중 [0.8,1,1.1,1.25,1.4] × 업종별 기본 생산(식량 3, 의료품 1, 가전 0.5, 사치품 0.2 단위/인·일, 임시).
**보정 목표**: 기준 도시(주거 4·상업 2·공업 2·16명)에서 12게임일 동안 식량 부족 0, 실업 0, 사업장 balance 음수 지속 없음.
이 조건을 만족하도록 수치를 조정하되 근거를 문서에 남긴다(기준을 낮춰 통과시키지 않는다).

## 8. 행복도와 이주/이탈 규칙 (사용자 확정 방향 + 제안 수치)

**행복도(0~100)** — 일 정산마다 갱신, 시작값 60.

| 요인 | 일 변화(제안) |
|---|---|
| 소득 있음(취업) | +1 |
| 소득 없음(무직 가구) | −4 |
| 식량 충족 | 0, 부족 시 −5×부족률 |
| 의료품 충족 | 0, 부족 시 −1×부족률 |
| 가전/사치품 충족(구매 대상 소득 구간일 때) | +0.5 / +0.5 |
| 상한/하한 | 0~100 클램프, 평형 쪽으로 서서히 회귀(+0.5/일, 요인 없을 때) |

**이주/이탈**
1. 행복도 ≤ 20이 **3게임일 연속**이면 `변두리 이주 대기`.
2. **변두리 이주**: **인프라 점수가 낮은 빈 가구 정원**으로 이사한다(사용자 확정 정의: 교육·취업 등 인프라가
   적게 충족되는 곳이 변두리. 맵 중앙일수록 인프라가 모여 점수가 높아지는 것은 결과이지 좌표 규칙이 아니다).
   - 주거 부지별 **인프라 점수(0~100)** 를 일 정산 때 계산. 단계 A 요인: 일자리 접근(일정 거리 내 빈/전체 일자리),
     상업 접근(소비재 구매처 거리), 전력 공급, 상수/하수 공급, 도로 연결. 교육·의료·소방·치안·공원은
     서비스 엔진(백로그 5번) 이후 같은 점수에 요인으로 추가한다(사용자 확정: 서비스 요인은 그 뒤에).
   - 인프라 점수는 행복도에도 반영(점수 높을수록 일 +, 낮을수록 일 −, 계수는 제안값).
   - 이주 대상: 현재 집보다 인프라 점수가 낮은(=변두리) 빈 정원 중 가장 낮은 곳부터. 변두리 생활비(임대료) 개념은 후속.
   - 이사 후 행복도 40으로 재시작, 이주 횟수 기록.
3. 갈 곳이 없으면(빈 정원 0) 또는 변두리에서도 다시 ≤20이 3일 연속이면 **도시를 떠난다**(가구 삭제, 이탈 기록·통계).
4. 이탈로 비게 된 집은 기존 규칙대로 새 외부 가구 유입에 쓰이지만, **실업 상태 유입을 막기 위해** 일자리 여유가 없으면 신규 입주 중지(기존 부트스트랩 규칙 유지).
5. 철거 가구 재배정(home_id=−1) 기존 정책과 구분한다(철거는 행복도 규칙이 아님).
6. 행복도 UI: 하단 UI 통합 이후 상태 줄에 평균 행복도 숫자만 표시(설명 문구 금지). 이번 단계에서는 모델 API/테스트까지.

## 11. 완료 기준 (단계 A)

1. 기준 예시가 12게임일 동안 §7 보정 목표 충족 (headless 실측)
2. 보존 법칙: 물자별 생산+수입 = 소비+수출+재고증가, 지급액 합 = 수령액 합. 일시정지/3배속/큰 시간 점프 동일 결과
3. 이웃 도로 연결 없음 → 수입 0, 연결 → 수입 발생, 연결 삭제 → 즉시 중단 (기존 38/38 영향 없음)
4. 무소득 가구: 행복도 하락 → 변두리 이주 → 빈 정원 없을 때 이탈, 각 분기 결정적 테스트(고정 seed)
5. city.funds 불변, 기존 전체 테스트(현재 21/21) 통과, 전력/수도 정산 회귀 무변경
6. 검증 로그·증거를 *-validation/ 규약으로 보존, SKILL_HANDOFF 갱신. 통근/물류/세금/발전 연료는 이번 단계가 아님을 문서에 명시

## 12. 사용자 결정 (2026-11-10 확정)

1. **변두리** = 교육·취업 등 인프라가 적게 충족된 곳. 인프라 점수로 판정(§8). 중앙 고점수는 자연 결과.
2. **발전소 연료 의존(단계 B) 승인. 연료 부족에 의한 정전은 의도된 게임 규칙.** 스위치로 도입하되
   단계 B 완료 시 기본값을 켬으로 할지는 결과 확인 후 결정. 동시 공급·흐름 표시 분리 원칙은 유지.
3. 임금(일급 30~100), 소득 구간, 이웃 교역 성향표(§5-1), 단가 계수는 **임시값으로 시작**. 테스트 후 안 맞으면 조정.
4. 서비스(교육/의료/소방/치안 등) 행복도·인프라 요인은 **서비스 엔진 이후** 추가.
