아직 없다. 차량이 주행하거나 병원 이름이 메뉴에 보이는 것만으로 이 순환이 완성되지 않는다.

## 후속 우선순위 제안

1. **현재 요청 마무리 이후**: 하단 검토 UI를 실제 플레이에 통합하고 공공시설의 접도·정면·
   배치·선택·통합 철거를 공통화한다. 병원/진료소 애셋을 별도 범위로 제작한다.
2. 드래그 구획과 수요 기반 자동 신축. 무료 구획/자동 신축 규칙을 유지하고 기존 클릭·수동
   성장과 구분한다. 공급·접도·충돌 판정은 공통화한다.
3. 주민·가구·일자리·사업장·소비/생산·재고의 최소 상태 모델. 실제 상태에서 통근/물류를
   발생시키고 고정 시험 차량을 현실 수요로 잘못 집계하지 않는다.
4. 세금·시설 유지비·예산과 명시적으로 승인된 경제값을 연결한다. 관리 CSV는 런타임
   로더가 아니며 미정 빈 값과 0, 제안과 적용을 구분한다.
5. 소방·치안·보건·교육·쓰레기의 사건/수요·직원·차량·처리 대기열을 차례로 연결한다.
   출동 차량은 일반 교통 예약 규칙을 존중해야 한다. 대중교통은 노선·승객 수요 이후 확장한다.
6. 저장/불러오기는 위 기능과 병행해 데이터 계약부터 정한다. 도로/부지 안정 ID와
   front_direction/front_road_id, utility 계량 소수잔액을 보존하고 왕복 검사를 만든다.
7. 목표 도시 규모를 정한 뒤 성능·모바일·배포를 검증한다. 현재 시험 통과를 상용 배포
   가능성이나 대규모 도시 처리 성능으로 해석하지 않는다.

저장·불러오기 기반은 후반까지 미루기보다 상태 모델 정립 시 함께 설계할 수 있다.
전체 구현을 이번 애셋 제작에 포함하지 않으며 각 항목은 다음 요청에서 범위를 정한다.
