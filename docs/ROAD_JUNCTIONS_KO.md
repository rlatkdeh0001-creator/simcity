# 도로 교차로 연결 · 2026-11-02 KST

## 최신 수정: 구획을 보존하는 직각 교차로

사용자 요청으로 바깥으로 부풀던 팔각형/사선 모서리를 없앴다.
교차로 포장은 접근 도로의 폭을 유지한 직사각 띠를 합친 모양으로 계산한다.
직각으로 만나는 도로는 경계도 직각으로 이어지므로 인접 구획을 사선으로 잘라먹지 않는다.
비스듬한 도로는 기존 도로 방향을 유지하며, 도로 밖 대각 쐐기를 임의로 채우지 않는다.
동일한 새 외곽을 렌더링·건물 충돌·배치 타일 제외에 사용한다.

[실제 게임의 구획 표시 화면](screenshots/junctions-square-zoning.png).
2차로 X자 사례에서 네 모서리의 도로 로컬 2×2 건설이 모두 가능하고,
교차 도로를 나중에 추가해도 그 모서리 집을 덮거나 철거하지 않는 것을 검사했다.
실제 노면 안에는 여전히 건물/시설/배치 타일이 들어갈 수 없다.

줄어든 노면에 맞춰 회전 곡선의 제어점을 차로 접선 교점으로 조정했다.
2/4차로 혼합 교차로의 모든 회전 중심 경로가 실제 아스팔트 안에 있는지 검사했다.
차종별 최소 회전반경/전체 차체의 물리 해석은 아래 기존 한계와 같이 미구현이다.
현재 교차로 검사 **46/46**, 전체 **15개 스크립트 통과**.
아래 최초 도입의 41개 검사/모서리 포장 설명은 이 수정으로 갱신된다.


도로를 가로질러 그리면 같은 지면의 교차 지점을 실제 교차로로 연결한다.
기존에는 겹쳐 보이는 도로를 주행 그래프가 거부했지만, 현재는 교차 지점에서 경로를
나누고 직진·좌회전·우회전 연결 곡선을 생성한다.

## 실제 동작

- X자·T자, 서로 다른 도로의 꺾인 끝점 연결, 비스듬한 교차를 처리한다.
  한 폴리라인이 자기 자신을 가로지를 때도 교차점으로 인식한다.
- 중심선의 교차를 기반으로 하며 같은 위치의 샘플 점/소수 좌표는 한 교차점으로 병합한다.
  차선 수가 다른 2/4차로도 연결한다. 노면이 가까이 보이기만 하는 지점에 자동 연결하지 않는다.
- 도로 원본은 그대로 두고 주행용 구간만 파생한다. 기존 불도저는 한 번 그린 원본 도로
  경로 단위로 철거하며 도로가 사라지면 교차로·차선 그래프도 재구성한다.
- 교차로 안을 가로막던 도로 가장자리/차선을 노면 패치로 정리하고 횡단보도를 그린다.
  횡단보도는 현재 시각 표현이며 보행자 시뮬레이션을 추가한 것은 아니다.
- 새 교차로의 실제 모서리 노면도 건물·시설 충돌 검사와 배치 타일 제외 영역에 포함한다.
  기존 건물을 덮어야 하는 교차로는 미리보기/건설 단계에서 거부한다.
- 우측통행 차로와 연결 곡선을 A* 경로에 포함한다. 진입 차로로 바로 되돌아가는 U턴은 만들지 않는다.

## 교차로 통행 제어

첫 구현은 **교차로 하나당 차량 한 대씩** 허용하는 보수적인 예약 방식이다.
앞에 선 차량부터 대기 순서를 기록하고, 출구에 차량 전체가 들어갈 공간이 있을 때만
진입을 허용한다. 진행 방향이 충돌하지 않는 차들도 동시에 보내는 최적화는 아직 없다.

차량이 곡선을 빠져나간 순간 바로 다음 차를 보내지 않고, 뒤쪽 차체와 최소 간격이
벗어날 때까지 예약을 유지한다. 길이가 긴 차량도 같은 기준으로 처리한다.
출구가 막히면 교차로에 들어가기 전에 기다리고, 기존 수동 적색 정지선도 지킨다.
기존 앞차 간격/가속·감속과 고정 30Hz 시뮬레이션은 유지한다.
연결 곡선 제한 속도는 30km/h로 둔 구현상 시험값이며 교차로 진입 전에 감속한다.
기존 일반도로 80km/h·고속도로 160km/h 상한은 바꾸지 않았다.

신호등 주기/다중 동시 통과/전용 좌회전 차로/우선도로/보행자/회전 차로 변경/
차종별 최소 회전반경·전체 차체의 물리 충돌 해석은 후속이다.
현재 도로에는 높이 정보가 없어 모두 같은 지면에서 연결한다. 고가·터널 입체교차는 미구현이다.
직렬로 매우 가까운 교차로의 짧은 수용 차로는 진입 공간 부족으로 막힐 수 있으며,
대규모 도시의 교차로 배분/공간 인덱스 최적화까지 검증한 것은 아니다.
중심선이 겹치는 중복 도로는 기존처럼 주행을 거부한다.

## 코드와 기존 기능

- `core/road_junctions.gd`: 중심선 교차·구간 나누기·노드 병합·접근 방향·노면 영역 계산.
- `core/city_model.gd`: 교차로 캐시, 건물/시설/구획과 교차로 노면 충돌, 도로 삭제 후 재구성.
- `main.gd`: 실제 도로 패치·횡단보도 렌더링. 설명 문구를 화면에 추가하지 않았다.
- `core/traffic_network.gd`: 우측통행 차선, 곡선 연결, 방향성 A* 그래프.
- `core/traffic_simulation.gd`: 예약/대기·차체 후미 확보·출구 공간 검사·곡선 진입 감속.
- `core/traffic_controller.gd`: 교차로 안에 차량을 새로 생성하지 않으며 실제 경로를 시드한다.
- `core/road_generator_traffic.gd`: 원본 RoadLane/RoadLaneAgent를 그대로 사용한다.
  새 곡선도 이 어댑터를 통과하며 원본 애드온 코드를 수정하지 않았다.

교차로는 기존 도로의 연결 기능이다. 별도 시설 가격·유지비·추가 요금을 책정하거나
차감하지 않았으며 경제 CSV·전력/수도 요금도 바꾸지 않았다.
배치 타일은 계속 구획/도로 메뉴에서만 보이고, 통합 불도저와 하단 UI는 유지한다.

## 실행·재현

```sh
godot --path cities_do junction_demo.tscn
python tools/validate_junction_update.py
godot --headless --path cities_do --script tests/test_junctions.gd
godot --path cities_do --resolution 1600x1000 junction_demo.tscn -- --record-junction=/tmp/junction-frames
python tools/build_junction_evidence.py --frames /tmp/junction-frames
```

실습 장면은 실제 게임 렌더러/차량 애셋/CityModel로 4차로 X교차로와 2차로 T분기를
구성한다. 차량은 실제 새 주행 그래프로 움직인다. 새 NPC 발생·도시 전체 통근·목적지
회전율을 구현한 것은 아니므로 유한 차량들이 종점에 서면 교통이 정체될 수 있다.
사진/GIF는 Xvfb+Mesa OpenGL 뷰포트 캡처이며 생성형 그림이나 합성 애니메이션이 아니다.
[증거 메타데이터·해시](screenshots/junctions-evidence.json)에 원본 프레임 수/크기/시간을 기록했다.
제한 환경의 Godot 명령은 기존 writable XDG 경로를 지정한다.
