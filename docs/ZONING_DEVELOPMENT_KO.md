# 드래그 구획과 자동 신축

2026-11-03 후속: [주민·교육·수요·통합 시계](POPULATION_TIME_KO.md)를 도입했다.
현재 기본 모드는 실제 입주민 수 기반 수요로 신축을 허가한다. 아래의 수요 미구현/기존 시간
설명은 최초 구획 구현 당시 범위이며, 기하 검사 fixture에서만 인구 수요를 끄고 재현한다.

2026-11-03 KST 사용자 확정 규칙을 구현했다. 주민·가구·일자리·수요 엔진은 다음 단계다.

## 조작과 확정 규칙

하단 검토 장면 `bottom_ui_preview.tscn`의 **구획 → 주거/상업/공업**을 선택한 뒤
지도에서 왼쪽 버튼을 누르고 드래그한다. 놓으면 화면 사각형 안에 중심이 들어오는
도로 로컬 격자를 녹색/청색/황색으로 지정한다. 짧은 클릭은 한 칸만 지정한다.
구획 해제도 같은 드래그 도구다. 미리보기는 반투명 사각형이며 확정 전에 건물을 만들지 않는다.
오른쪽 클릭·Esc·도구/탭 전환·지도 이동/줌은 진행 중인 구획 드래그를 취소한다.
지도에서 시작해 HUD 위에서 놓아도 취소한다. 화면 좌표 사각형이므로 대각선 도로의
격자도 자기 도로의 회전한 정사각형 형태를 유지한다. 색칠 도중에는 미리보기만 그린다.

- 1칸=4×4m. 신축은 같은 용도로 지정된 한 블록의 2×2칸=8×8m 부지만 사용한다.
- 구획 지정·해제·민간 자동 신축에 시 건설비를 부과하지 않는다. 시작 자금은 50,000 doth.
- 기존 공통 접도 판정으로 보도 포함 도로 바깥 경계에서 부지 앞면까지 최대 1.5m를 검사한다.
  도로 바로 옆에서 신축하고, 꼭짓점 하나만 가까운 부지는 거부한다. 고속도로는 접도 불가다.
- 깊은 격자에도 용도는 지정할 수 있지만, 접도한 2×2 부지가 아니면 신축하지 않는다.
- 다른 용도를 덧칠하거나 해제해도 기존 건물의 ID·용도·외관·정면·위치를 바꾸거나 철거하지 않는다.
  기존 건물을 바꾸려면 공통 불도저를 사용한다. 철거 후 색칠이 남아 있으면 다시 신축될 수 있다.
- 도로 추가/철거 후에도 살아 있는 안정적인 격자 ID의 색을 유지한다. 도로·교차로와 충돌해
  사라진 격자의 지정만 지운다. 기존 건물은 도로가 사라져도 일괄 이동·철거하지 않는다.
- 색칠과 격자는 구획 또는 도로 뷰에서만 보인다. 숨겨도 지정 데이터와 신축 시계는 유지한다.
- 이 기능의 ‘신축’은 건물 생성이다. 실제 주민 입주·상점 개업·공장 생산을 시뮬레이션하지 않는다.

메인 `main.tscn`의 기존 구획 도구에도 같은 제스처/API를 연결했다. 기존 왼쪽 조작 패널은
유지했으며, 메인 플레이의 전체 하단 UI 통합까지 완료했다는 뜻은 아니다.

## 임시 신축 속도와 후속 수요 연결

`core/growth_config.gd`의 **2게임초마다 최대 한 동 시도**는 임시 개발 페이싱이다.
이 값은 실제 주민·기업 수요나 수입을 계산한 결과가 아니다. 일시정지/3배속은 기존
하단 검토 장면의 시뮬레이션 시간과 함께 작동한다. 구획 탭을 닫아도 신축을 계속한다.
요금 계산은 전력/수도 기존 시간 경로를 유지하며 구획 기능이 별도 과금을 만들지 않는다.

시간을 누적해 처리하므로 프레임마다 난수를 뽑지 않는다. 한 호출에서 최대 8틱을 처리하고
남은 시간을 보존한다. 각 틱에서 최대 256개 지정 칸을 순환 검사하며, 불가능한 부지가
다른 블록·용도를 영구히 막지 않게 커서를 이어간다. 빈 지정 상태에서는 신축 시간을 쌓지 않는다.
주민/일자리 모델을 도입한 후 여기의 신축 허가를 수요량으로 제한할 예정이다.
프레임 독립성 검사는 처리 상한을 넘지 않는 동일 시간 시퀀스에 대해 수행했다.
대규모 도시·장시간 오프라인 시뮬레이션을 검증한 것은 아니다.

신축은 `parcel_placement_error` → `add_building_at` → `orient_building`의 기존 경로로
검사·배치한다. 겹침·경계·도로·교차로·발전/상하수 시설 충돌을 계속 검사한다.
자동 신축 건물의 수동 성장도 확장 부지 전체가 원래 용도로 지정되어 있어야 한다.
기존 수동 시나리오 건물과 성장 확률/수치 규칙은 유지한다. 자동 밀도 성장까지 추가한 것은 아니다.

## 외관과 데이터 범위

주거 카탈로그의 2×2 시안은 기존 `growth_enabled:false`를 유지했다. 상업·공업용
등록 모델도 없으므로 현재 2×2 신축에는 기존 용도별 임시 입체 외형을 사용한다.
주거 모델을 상업·공업으로 오표시하거나 새 모델/승인되지 않은 외관을 강제 등록하지 않았다.
이후 신축 사용이 승인된 해당 크기 모델이 등록되면 카탈로그 매칭 경로를 사용한다.
부지·건물 확대나 PNG 변형으로 외관을 맞추지 않는다.

`city_model.zone_designations`는 안정적인 parcel ID → 용도 사전이고 기존 도로 로컬
격자와 독립해 보존한다. `automatically_developed`는 신축 건물의 구획 확장 제한용 표식이다.
이 상태는 **현재 실행의 메모리 데이터**다. 파일 저장/불러오기 기능을 구현하지 않았다.
향후 저장에는 구획 용도·도로 로컬 frame/ID·신축 시간/커서와 건물 정면/출입 도로 ID를 포함해야 한다.

## 검증과 재현

로컬 construction/GDScript/headless-testing 지침을 사용했다. 외부 스킬·애셋을 새로
설치하거나 차량/화장터를 재생성하지 않았다. 원본 스킬/라이선스는 변경하지 않았다.
프로젝트 자체 construction 지침에 이번 규칙을 갱신하고 인계장에 같은 작업으로 기록했다.

```sh
export XDG_DATA_HOME=/tmp/cities-do-data
export XDG_CONFIG_HOME=/tmp/cities-do-config
export XDG_CACHE_HOME=/tmp/cities-do-cache
godot --headless --editor --import --path cities_do --quit
python3 tools/validate_zoning.py
# 실제 X 서버 필요. 이번에는 기존 /tmp Xvfb :99 + Mesa llvmpipe 사용.
DISPLAY=:99 godot --path cities_do --audio-driver Dummy --rendering-method gl_compatibility --script /workspace/simcity/tools/capture_zoning.gd
```

접도·기존 건물 보존·도로 ID 보존/철거·순환 검사·HUD 취소·탭 전환·자동 건물 성장 제한을 포함한다.

headless 검사나 생성형 이미지로 대체하지 않았다. 모바일/대규모 도시 성능은 미검증이다.
