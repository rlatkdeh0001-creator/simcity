## 등록 / 매칭

- 신규14 = 주거4·상업4·공업6. 실제 GLB/PNG/spec/썸네일14개씩, `assets/growth_14.json`.

- 기존 `building_catalog.gd`에서 (용도, 정사각 부지, 성장 단계에 따른 밀도)로 선택한다.
  단계1·2 small / 3·4 medium / 5+ large. 밀도는 원본 category/density이며 부지 크기로 정하지 않는다.
- 동일 부지/동일 밀도 후보를 우선한다. 없으면 같은 부지의 가장 가까운 밀도, 동률이면 낮은 밀도를 선택한다.
  해당 용도/부지 후보 자체가 없을 때만 기존 임시 블록으로 돌아간다. 다른 크기 모델을 늘이지 않는다.
- 같은 부지·같은 밀도에서 현재 후보이면 외관을 유지한다. 단계2→3, 4→5나 부지 변경 시 기존 assign 경로로 재매칭한다.
- 맨션2종의 **4×4/4층/min_level2**를 유지했다. 새 규칙의 단계2는 small 우선이고 단계3·4 medium 후보가 두 맨션이다.
  레벨1에 맨션을 쓰지 않는다. 그 외 외관 min_level은1로 통일해 시안의 낡은 최소레벨이 같은 부지 폴백을 막지 않게 했다.
  이것은 레벨·부지·성장 확률 변경이 아니다.
- 기존 add_building/add_building_at에 초기 외관 assign만 한 줄씩 연결했다. 개발/성장/랜덤/행복도/수요/가격 수치는 변경하지 않았다.
- 기존 검사 전용 30종 인덱스/spec는 과거 검사 상태를 보존한다. 실제 성장 활성화는 건물 카탈로그의18개에만 반영하며
  원래 검사창·전시 경로도 그대로 유지한다. 운영/생산량은 여전히 미적용이다.
