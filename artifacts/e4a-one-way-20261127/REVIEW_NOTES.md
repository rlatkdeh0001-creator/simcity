# E4a — 편도 지상 도로 4종

## 한 일

- 기존 양방향 카드와 저장 형식을 유지하고 편도 1·2·3·4차로를 추가했다. 전체 폭 6/12/12/20m, 차로 폭 3.5m, 진행 방향은 그린 순서이며 높이는 0m에 고정된다.
- 실제 편도 차로와 허용된 교차로·이음 연결만 만들고, 같은 방향과 프로필의 직선만 덧씌울 수 있다. 편도 1차로는 진행 오른쪽 보도에만 구획을 만들며 건물 정면도 그 경계를 기준으로 한다.
- 정류장과 버스는 오른쪽에서만 합법적으로 정차·진행한다. 확정 도로 변경 뒤 오래된 차량 그래프를 사용하지 않는다. 도로가 비는 순간을 거쳐도 새 도로가 들어오면 합성 교통을 재시드하고 독립 일시정지를 보존한다.
- 표시 화살표는 미리보기와 확정 도로가 공용 도형을 사용한다. 고정 노면·구조물과 이동 차량의 동기화는 분리했다.

## 검증

- 기준선: §8.1 기존 28/28 스위트, 1,920/1,920 단언. 최종 합산 헤드리스 46/46, 144,540/144,540; 실제 화면 무캡처 420/420, 캡처 430/430. 최종 변경은 기존 독립 검수 지적에 대한 표적 재검증으로 확인했으며, 최종본 전체를 독립적으로 승인받았다는 뜻은 아니다.
- 독립 검수가 짚은 실제 도로 도구의 교통 초기화는 실제 불도저→역방향 편도 재건설 시험에서 2개 단언 실패로 재현했다. 확정 시 도로 변경 번호로만 교통을 갱신하도록 고친 뒤 무캡처 양 모드 396/396. 실제 worker 경계에서 확정 먼저·후속 거절 순서가 올 때도 대기 중에는 기존 차를 유지하고, 확정 시 한 번 재시드한 뒤 거절 시 유지한다는 헤드리스 확장 시험 420/420 (`e4a-review-20261127-fifo`). 이 수치는 최종 통합 관문과 별개다.
- 1차 독립 검수 지적을 반영했다. 150° 급커브와 방향별 2→3 도색 순서 검사는 26/26, 화살표 겹침/정지 미리보기 검사 35/35, 기존 지상 배치·정면 검사 66/66. 구형 저장 버스는 작업자가 도로·시설 배열을 교체하기 전에 원래 그래프에서 경로 증거를 복구한다. 원래 그래프가 사라진 채 저장된 기존 동결 버스는 추정하지 않는다.
- 재검수에서 놓친 22° 편도 2→3차로 이음 등을 추가했다. 실제 포장 위를 지나는지 여러 각도·단면·시공 순서에서 샘플링한 기존 794/794 결과와, 양방향 그래프 64개가 같은지 비교한 결과를 보존한다. 지상 끝점·4m 연결 길이·혼합 높이의 노면 충돌·무관한 지하 교차로를 구분하는 두 모델 API의 보강 시험은 108/131 → 131/131이었다. 최종 통합 결과와는 별개다.
- 앞선 통합 실행에서 작업자 parity 2종이 240초에 시간 초과했다. 헤드리스의 인위적인 30FPS 제한을 빼도 240초에는 완료되지 않았다. 기존 전수 러너의 보조 parity 전용 900초 한도로 재실행한 결과 native mailbox는 86,410/86,410 및 정상 종료, managed는 54,010/54,010 뒤 종료 단계에서 `Fatal error.`, `0xC0000005`, ObjectDB 누수 경고를 남겼다. managed는 exit 0이어도 통과로 처리하지 않는다. 나머지 44/44(4,117/4,117), §8.1 기존 28/28(1,920/1,920)은 해시가 동일할 때만 재사용한다. 이전 오류/시간 초과 로그는 `e4a-final-20261127`, `e4a-final-20261127-v2`, `e4a-final-20261127-parity-long`에 보존했다. 최종 원시 로그와 결과 JSON은 `raw-verification.zip`으로 바이트 그대로 보존한다.
- 키 타입 복원 뒤 최종 소스의 실제 GL 캡처를 확인했다(`e4a-final-20261127-v4`): 무캡처 420/420, 두 장 캡처 430/430, 각 모드 진단 없음. 관리형 parity도 같은 소스·DLL·설정을 검증한 격리 사본에서 54,010/54,010, 정상 종료했다. 과거 종료 오류의 원인은 확인하지 못했고, 수리했다고 보지 않는다.
